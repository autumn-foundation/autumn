# Migration versions grandfathered by scripts/check-migration-versions.sh
#
# Every entry here violates the version rules that gate now enforces: a
# day-granularity `HHMMSS` of `000000`, an all-zero/pre-epoch version, or a
# component that is not a real time (`20260530300000` has hour 30).
#
# They are listed rather than fixed because THEY CANNOT BE RENAMED. Diesel
# records applied migrations by version in `__diesel_schema_migrations`, and
# `autumn_migration_checksums` makes the version a PRIMARY KEY. Renaming a
# migration that has already run makes the framework consider it unapplied
# and run it again against production databases.
#
# This file is a record of debt, and it should only ever shrink -- an entry
# comes out when its migration is deleted, never because a new migration was
# added. A new migration must satisfy the rules:
#
#     autumn generate migration <Name> [field:type ...]
#     autumn schema diff --write-migration --name <name>
#
# Both mint a full YYYYMMDDHHMMSS, so two authors collide only if they
# generate in the same second.
#
# Note what is NOT here: `autumn/migrations/20260530200000_create_feature_flags`
# passes, because `200000` is a real time. The rule is precision, not the
# presence of zeros.
