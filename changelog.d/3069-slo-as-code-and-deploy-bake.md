### Added

- **slo:** declare SLOs in `autumn.toml` as `[[slo]]` tables (`name`, `objective`, `sli = "availability" | "latency"`, `route`, `threshold_ms`). The new `autumn_web::slo` module checks them. The `prod` profile's strict config accepts them (issue #3069).
- **cli:** `autumn slo generate` writes Prometheus recording rules and multiwindow burn-rate alerts (14.4× over 1h/5m, 6× over 6h/30m, 1× over 3d/6h), a `PrometheusRule`, a Grafana dashboard, an Argo Rollouts `AnalysisTemplate`, Flagger `MetricTemplate`s and Helm values to `deploy/slo/`. `--check` fails when the files are out of date. See `docs/guide/slo.md` (issue #3069).
- **deploy:** a post-cutover bake. With `[deploy.bake] duration_secs` or `autumn deploy up --bake-secs N`, each host samples `/actuator/metrics` after its cutover and rolls back when the 5xx ratio or the latency is above the limit. The default limits come from the `[[slo]]` tables (the 14.4× burn rate). A fleet halts with the step `bake` and rolls back every host on the new release. The bake is off by default (issue #3069).
- **release:** `autumn release init --target kubernetes` writes a Helm chart (`deploy/helm/`) and a Kustomize base (`deploy/kustomize/base/`) with `/startup`, `/live` and `/ready` probes, a `preStop` hook, a grace period longer than the drain window, a `PodDisruptionBudget`, and opt-in Argo Rollouts or Flagger canaries. See `docs/guide/kubernetes.md` (issue #3069).
