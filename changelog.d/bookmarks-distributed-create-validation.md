### Fixed

- **🧭 Wayfinder: validate and redisplay the Add Bookmark form in
  `examples/bookmarks-distributed` (validation wired 0/1 → 1/1):** the
  example's only write path, `POST /bookmarks`, extracted straight into
  `NewBookmark` and inserted it with no call to `.validate()` anywhere —
  worse than the already-fixed "bounces to a generic error page"
  anti-pattern (`saas`/`teams`/`reddit-clone`/`cms`), because there was no
  rejection path at all: an empty title or a non-URL string in `url` was
  silently persisted and then rendered back into the list as if it were
  valid data, even though `Bookmark`'s own `#[validate(url)]` /
  `#[validate(length(min = 1, max = 200))]` attributes (and `NewBookmark`'s
  derived `validator::Validate`, generated by `#[model]`) were sitting
  right there unused. Fix: `create` now calls `.into_changeset()` and, on
  an invalid submission, re-renders the same `Add Bookmark` form at HTTP
  422 with every submitted field preserved and an inline error next to the
  offending input — the same `Changeset`/`text_input` idiom the sibling
  `examples/bookmarks` already uses. New unit tests cover the rejected-url
  case, the rejected-title case, that unrelated valid fields survive a
  rejection, and the clean (no-error) render.
