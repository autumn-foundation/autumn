# MCP Tasks Extension

> **Status: executed.** Spec: `io.modelcontextprotocol/tasks`
> ([overview](https://modelcontextprotocol.io/extensions/tasks/overview),
> [ext-tasks](https://github.com/modelcontextprotocol/ext-tasks), revision
> `2026-07-28`). Prior work: #1117 (MCP tools), #1118 (SSE streaming), #1691
> (agent audit).

## Gap audit

| Item | State before this plan | Gap |
| --- | --- | --- |
| Capability | `initialize` lists `tools` only. | No `extensions` entry. |
| `tools/call` | Blocks until the handler returns. | No task handle. |
| Envelope timeout | The global deadline wraps the whole `POST /mcp`. | Long work fails over MCP. |
| `tasks/get`, `tasks/update`, `tasks/cancel` | Not served. | `-32601`. |
| Task store | None. | No state, no TTL, no owner. |

## Facts (white hat)

- The client opts in on each request with
  `params._meta["io.modelcontextprotocol/clientCapabilities"].extensions["io.modelcontextprotocol/tasks"]`.
- The server decides per request. It must not return a task to a client
  that did not opt in.
- `CreateTaskResult` is flat: `resultType: "task"`, `taskId`, `status`,
  `createdAt`, `lastUpdatedAt`, `ttlMs`, `pollIntervalMs`.
- `tasks/get` returns the task with `resultType: "complete"`, plus `result`
  (completed) or `error` (failed).
- A tool result with `isError: true` is `completed`, not `failed`.
- Errors: unknown task `-32602`. Missing capability on `tasks/*` `-32021`.
- Task IDs must be unguessable. Each task request must be authorized.
- Only `tools/call` can create a task.
- Notifications (`notifications/tasks`) are optional. Polling is the default.
- The MCP dispatch replays through the router clone. The clone applies the
  route's own timeout. The envelope applies the global deadline.

## Brainstorming

1. Per-tool opt-in flag: `#[api_doc(mcp, task)]` and `Route::mcp_task()`.
2. Make every call a task when the client opts in.
3. A builder list of tool names.
4. In-memory task store, bounded by count and TTL.
5. A pluggable `TaskStore` trait (Redis, database).
6. Run the task on `tokio::spawn`, abort on cancel.
7. Run the task as an Autumn background job.
8. Bind each task to a digest of the caller's credentials.
9. Advertise the capability only when a task tool exists.
10. `notifications/tasks` over `subscriptions/listen`.
11. Implement the `2025-11-25` core tasks (V1: `task` param, `tasks/result`,
    `tasks/list`).
12. Add `Mcp-Name` and `Mcp-Method` to the CORS preflight allow-list.
13. Fall back to a blocking call when the store is full.

Selected: 1, 4, 6, 8, 9, 12, 13. Item 2 adds a poll round trip to fast tools.
Item 3 can drift from the routes. Item 5 needs a serialized result and a
cross-node abort; the in-memory store is the seam for it later. Item 7 needs
the `db` feature and a serializable request. Item 10 needs a server stream
that Autumn does not serve (`GET /mcp` is 405). Item 11 is a different
protocol revision that Autumn does not negotiate.

## Reverse brainstorming ("how do we make this fail?")

| Failure we could cause | Prevention |
| --- | --- |
| Caller B reads caller A's result. | The task stores a SHA-256 owner digest (`Authorization`, session cookie, tenant header, mTLS fingerprint). A mismatch returns the same `-32602` as an unknown ID, so no oracle. |
| An attacker guesses task IDs. | 256-bit IDs from the injected entropy source. |
| A flood of tasks uses all memory. | `max_tasks`, a per-client-IP `max_tasks_per_caller` and a `max_stored_bytes` budget. When a count cap is reached, the call runs blocking. A result over the byte budget becomes a tool error. |
| A caller rotates `Authorization` to get a new quota. | The quota key is the proxy-resolved client IP, not the credential. |
| A result stays in memory forever. | TTL from creation. Expired tasks are purged. A timeout stops the job at the TTL, also with no new request. |
| A cancel after the handler ends loses the result. | The job stores the result before it writes the audit outcome. |
| A task returned before `tasks/get` can see it. | Insert into the store, then spawn, then respond. |
| A race sets `completed` after `cancelled`. | Terminal states never change. Only `working` can move. |
| A panic leaves the task in `working`. | The pipeline turns a handler panic into HTTP 500 (`completed`, `isError`). `catch_unwind` marks any other panic `failed` with `-32603`. |
| Cancel stops the work but the audit trail has no outcome. | A drop guard writes the outcome with `result = task_aborted`. |
| A detached task skips load shedding. | The detached replay does not carry the envelope exemption, so it takes its own slot. |
| A client without the capability gets a task. | The capability check runs on each request. Otherwise the call is blocking. |
| A batch hides `tasks/*` from the owner check. | `tasks/*` in a batch is refused, like `tools/call`. |
| Bad arguments become a `failed` task. | Validation runs before the task exists, so the client gets the normal error. |
| Tests depend on wall time. | Timestamps use the state clock. IDs use the state entropy. |

## Six thinking hats

- **White:** see "Facts".
- **Red:** an agent that sees "working" for an hour with no progress is
  unhappy. A short default poll interval and a clear `statusMessage` help.
- **Black:** state is per process. A load balancer that does not route on
  `Mcp-Name` sends polls to the wrong replica. Results are lost on restart.
  A `Set-Cookie` from a task handler cannot reach the client.
- **Yellow:** long tools now work over MCP, because only the route timeout
  applies to a task. Clients can reconnect and poll.
- **Green:** reuse the buffered packaging, the audit record and the replay
  extensions. A `stream` tool can also be a `task` tool: a task buffers the
  stream into the final result.
- **Blue:** TDD order: integration tests (red, compile), API flags (red,
  assertions), store and handlers (green), refactor, docs, review.

## Decisions

1. `#[api_doc(mcp, task)]` and `Route::mcp_task()` set `ApiDoc::mcp_task`.
2. `McpTaskConfig` sets `ttl` (1 h, minimum 1 s), `poll_interval` (1 s),
   `max_tasks` (1024), `max_tasks_per_caller` (64, per client IP) and
   `max_stored_bytes` (256 MiB). `AppBuilder::mcp_tasks` and `TestApp::mcp_tasks` install it.
3. `initialize` adds `capabilities.extensions["io.modelcontextprotocol/tasks"]`
   when one or more tools are task tools. With no task tool, `tasks/*` is
   `-32601`.
4. `tasks/update` acknowledges and ignores `inputResponses`. Autumn never
   enters `input_required`.
5. Code review (spec, security, concurrency, conventions) found and fixed: a
   lost result on a late cancel, a lazy TTL, no per-caller quota, a dead
   actor part in the owner digest, a zero TTL, unsafe JSON integers, and
   wrong docs on panics.
6. Out of scope: `notifications/tasks`, `server/discover`, `2025-11-25` core
   tasks, a durable store.

## Follow-up: protocol `2026-07-28` (in this PR)

Code review found that the Tasks extension and `capabilities.extensions` are
part of protocol `2026-07-28`, which Autumn did not serve. The PR author
chose to add that revision in this PR.

### Brainstorming

1. Replace the legacy flow with the modern one.
2. Dual-era: pick the era per request from `_meta`.
3. A second endpoint path for the modern era.
4. Stamp results in each builder, or once at the boundary.

Selected: 2 and 4 (at the boundary). Item 1 breaks every legacy client.
Item 3 needs a second mount and a second CORS setup, and the spec uses one
endpoint for both eras.

### Reverse brainstorming

| Failure we could cause | Prevention |
| --- | --- |
| A legacy client breaks. | Without modern `_meta` (or a modern header), the old code path runs. The existing MCP suite runs unchanged. |
| A proxy routes on a header that the body contradicts. | `MCP-Protocol-Version`, `Mcp-Method` and `Mcp-Name` must match the body, else `-32020` (HTTP 400). |
| A modern client gets a 200 for an unknown method. | `-32601` with HTTP 404. |
| A batch hides a modern request. | A batch with a modern message or header is `-32600` (HTTP 400). |
| A shared cache serves a gated catalog. | `cacheScope` is always `"private"`. |
| A streamed result has no `resultType`. | The SSE projection stamps the final message. |
| A proxy reads a second copy of a header. | A repeated standard header is `-32020`. |
| A dual-era client falls back to legacy on a modern error. | Errors omit a `null` id; the version check runs before the capability check; unknown methods get 404 before the `Mcp-Name` check. |

### Six thinking hats

- **White:** the modern revision removes `initialize`, `ping`, sessions and
  the GET stream; adds `server/discover`, per-request `_meta`, `resultType`,
  header mirroring and three new error codes.
- **Red:** two eras on one path can confuse operators. The guide lists the
  rules in one table.
- **Black:** re-parsing a buffered JSON result to stamp it costs one parse
  per modern call.
- **Yellow:** stock `2026-07-28` clients (and the `ext-tasks` client) can now
  use Autumn, tasks included.
- **Green:** reuse the legacy handlers; add the modern fields at the edge.
- **Blue:** TDD: `mcp_modern` tests (red), `mcp/modern.rs` and routing
  (green), docs, review.

### Out of scope

`subscriptions/listen` (the catalog never changes, so `listChanged` is
`false`), multi round-trip requests (Autumn never needs client input),
`x-mcp-header`, and per-request log levels.
