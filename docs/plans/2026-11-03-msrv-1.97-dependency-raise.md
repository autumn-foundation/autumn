Record each dependency that cannot move, with the cause and the revisit
trigger.

## Brainstorming

1. Use the resolver. `resolver = "3"` picks versions that fit
   `rust-version`. A higher MSRV lets `cargo update` select newer versions.
2. Remove the AWS caps. Some held the old MSRV. The others worked around
   compile errors that current AWS SDK releases do not have.
3. Raise the semver toolchain in `publish-gate.yml` to the MSRV. Cargo does
   not build a crate on a toolchain below its `rust-version`.
4. Raise one major at a time. Compile after each one. Fix the call sites.
5. Change the generated-app stamps too. The generator conformance tests
   compile a generated app, so they prove the stamps.
6. Remove `russh` from the lock. `testcontainers` 0.27 pins `russh` 0.60,
   and the fixed 0.60.3 pins prerelease `ecdsa` and `aes-gcm`. These
   conflict with the stable releases that `aws-sigv4` 1.6.2+ and
   `webauthn-rs` 0.6 need. The resolver then picks `russh` 0.60.1, which has
   RUSTSEC-2026-0154. The Pebble test is the only `russh` user (the
   `host-port-exposure` SSH tunnel). It can use the Docker `host-gateway`
   alias instead.
7. Change the current docs. Do not change history (`CHANGELOG.md`, released
   migration guides, reports).

## Reverse brainstorming: how to make this fail

| Way to fail | Prevention |
| --- | --- |
| A doc or workflow keeps `1.88.0` | Add `1.88` strings to the stale-text test. `check-msrv.sh` and `check-toolchain-pin.sh` gate the workflows. |
| The semver job runs a toolchain below the MSRV | `check-msrv.sh` fails when the semver pin is below the MSRV. |
| A bump makes two copies of a large crate stack | Hold `ed25519-dalek`. Raise `p256` only for the RUSTSEC-2026-0387 fix. Count `reqwest` majors in a test. |
| A `reqwest` type change breaks apps without notice | Write a breaking changelog fragment and a migration section. |
| `reqwest` 0.13 `rustls` adds `aws-lc-rs` to every app | Use `rustls-no-provider` and give each framework client a `ring` config. |
| A framework client panics with no crypto provider | A source scan test rejects a bare `reqwest` client build. |
| New clippy lints fire because the clippy `msrv` is higher | Run clippy with the CI pin (1.99.0) before push. |
| The two S3 crates drift apart | A test compares their AWS pins. |
| A generated app does not compile | Run `generated_auth_totp_cargo_checks` and `generated_auth_passkeys_cargo_checks`. |
| Edit history files | Change only current-state files. |
| A raise forces another crate down to a version with an advisory | Diff the lock for downgrades. Check each against RustSec. |
| A raise changes runtime behavior that no compile error shows | Run the unit tests with every CI feature. wasmi 2.0's tail-call dispatch let a guest overflow the host stack, in release too. |

## Six thinking hats

- **White (facts):** The local toolchain is 1.97.0. The CI pin is 1.99.0.
  Rust 1.97.0 was released on 2026-07-09.
- **Red (feel):** A big dependency diff is hard to review. Put each hold in
  one table, so the reviewer sees what did not move and why.
- **Black (risk):** STABILITY.md asks for an MSRV that is 6 months old.
  1.97.0 is 4 months old. The owner asks for this bump. The next release is
  a pre-1.0 minor, which can break. So the change is a **Breaking** entry
  with a migration section. `reqwest` 0.13 is also breaking: its types are
  in the `oauth2` and media plugin APIs.
- **Yellow (value):** The RUSTSEC-2026-0253 waiver for `lru` 0.16 can go.
  `webauthn-rs` 0.6 removes OpenSSL from the build. One `reqwest` major
  remains in the build.
- **Green (ideas):** Make the semver toolchain floor a gate, not a comment.
  Make the S3 pin parity a test.
- **Blue (process):** Plan, write failing tests, make them pass, refactor,
  review, record evidence for each acceptance criterion.

## Acceptance criteria

   different value.
2. AC2: `clippy.toml` `msrv` is `1.97.0`.

   quickstart matrices) is `1.97.0`. `check-msrv.sh` and
   `check-toolchain-pin.sh` pass.

   (`cargo update`). The `fuzz` and `island-flock` lock files too.
9. AC9: The MSRV-only AWS caps are gone. The two S3 crates have the same
   AWS pins, and a test checks this.
10. AC10: `Cargo.lock` holds one `reqwest` major. A test checks this.
11. AC11: Generated apps stamp the raised versions. The two generated auth
    compile tests pass.
12. AC12: `cargo check --workspace --all-targets` passes on 1.97.0.
13. AC13: `cargo clippy --workspace --all-targets -- -D warnings` passes on
    the CI pin 1.99.0. `cargo fmt --check` passes.
14. AC14: The tests for the changed modules pass.
15. AC15: A changelog fragment and a `next.md` section record the MSRV and
    the breaking `reqwest` change.
16. AC16: `cargo deny` advisory ignores that the bump makes obsolete are
    removed.
17. AC17: Framework `reqwest` clients keep `ring` and `webpki-roots`. No
    framework source builds a bare `reqwest` client. A test checks this.
18. AC18: The lock file has no downgrade to a version with a RustSec
    advisory. `russh` is not in the lock. The Pebble test passes with the
    `host-gateway` alias.
19. AC19: `webauthn-rs` 0.6 needs no OpenSSL. `autumn doctor`, the Windows
    CI journey and the generator guide no longer ask for OpenSSL or vcpkg.
20. AC20: A guest cannot overflow the host stack. Both wasmi users turn on
    `portable-dispatch`. A regression test runs a failing `memory.grow` loop
    on a 2 MiB thread.

## Residual risks

- wasmi 2.0.0 was held at 0.40 in 0.9.0, because it crashed on Windows when
  wasmi and its caller had different optimization levels. That crash matches
  the tail-call stack growth that `portable-dispatch` removes. The Windows
  `test` lane must pass the plugin sandbox and edge host tests before merge.
- The semver job has not run on 1.97.0. Run `publish-gate` before a release.
- The `MSRV (1.97.0)` check name is new. Update branch protection if it lists
  `MSRV (1.88.0)`.
