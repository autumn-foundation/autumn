Non-vacuousness check for job_dispatch_carries_no_ambient_tenant
==================================================================

The test has two independent phases; each was verified separately against
the real code path it claims to exercise, since a Codex review on this PR
correctly flagged that the original single-phase version (asserting only
on `perform_enqueued_jobs()`'s result) never actually drove the real
in-process worker's own dispatch path, and — worse — was racy against it:
the worker runs the same job concurrently and writes to the same shared
static, so a leak specific to the worker's dispatch could have been
silently overwritten by perform_enqueued_jobs()'s own (correct) result
before the assertion ever read it.

Phase 1 — the real in-process worker's dispatch path
------------------------------------------------------

`run_job_handler_inner` in autumn/src/job.rs is, per its own doc comment,
"the single choke point all three backends run handlers through." Injected
a fake tenant scope around the actual handler *poll*, not just its
construction (the first attempt wrapped `(handler)(state, payload)`'s
*construction* in `sync_scope`, which is a no-op for an async fn — the
task-local has to wrap the `.await` that actually polls it):

    let next = Box::pin(async move {
        let future_res = std::panic::catch_unwind(std::panic::AssertUnwindSafe(|| {
            (handler)(state, payload_for_handler)
        }));
        let future = match future_res {
            Ok(f) => f,
            Err(panic) => std::panic::resume_unwind(panic),
        };
        crate::tenancy::CURRENT_TENANT
            .scope(Some("fake-leaked-tenant".to_string()), future)
            .await
    });

Reran:
  cargo test -p autumn-web --test integration_tests --features test-support \
    -- job_tenant_scope --nocapture

Result: FAILED, on exactly phase 1's assertion:

thread 'integration::job_tenant_scope::job_dispatch_carries_no_ambient_tenant' (637) panicked at autumn/tests/integration/job_tenant_scope.rs:178:5:
assertion `left == right` failed: the in-process worker's own dispatch must not observe an ambient tenant
  left: Leaked("fake-leaked-tenant")
 right: NoTenant

Reverted (git diff -- autumn/src/job.rs empty afterward).

Both synthetic leaks were caught immediately and precisely (naming the
leaked tenant id), each on the phase whose real dispatch path it was
injected into, with no cross-phase masking. Only the test file itself
(autumn/tests/integration/job_tenant_scope.rs) is committed; both
production-code edits above were reverted after use.

Precondition check — the enqueue route actually resolves the expected tenant
--------------------------------------------------------------------------

A second Codex review round correctly noted that the test never verified
its own precondition: if tenancy middleware ever stopped applying to
/enqueue-probe (config regression, route exemption), the route would still
enqueue and both phases would correctly observe NoTenant — passing green
while never actually exercising an enqueue performed under ambient tenant
context.

Added an explicit check in enqueue_probe() via the Tenant extractor: the
route now 500s with a named message if the resolved tenant isn't exactly
"tenant-a-sentinel", rather than silently enqueuing anyway.

Verified non-vacuous two ways:

1. Omitted the x-tenant-id header entirely. Result: tenancy_middleware
   itself already fails closed —

     assertion `left == right` failed: expected 200 OK, got 400 Bad Request.
     Body: {...,"detail":"Missing required tenant header: x-tenant-id",...}

2. Sent a different tenant ("wrong-tenant") so extraction succeeds but
   resolves to the wrong tenant — only this new explicit check catches it:

     assertion `left == right` failed: expected 200 OK, got 500 Internal Server Error.
     Body: {...,"detail":"Internal server error",...}

   (the 500 is enqueue_probe()'s own guard firing; without it this case
   would have proceeded to enqueue and the test would have passed for the
   wrong reason.)

Both temporary header changes were reverted immediately after
(git diff -- autumn/tests/integration/job_tenant_scope.rs shows only the
permanent Tenant-extractor guard as a real change, not a header edit).

Third Codex round — the Tenant extractor itself has a fallback that masks this
--------------------------------------------------------------------------------

A third Codex review round correctly noted that the previous fix (checking
the `Tenant` extractor's resolved value) was itself still vacuous:
`Tenant::from_request_parts` (autumn/src/tenancy.rs) checks CURRENT_TENANT
first, but *falls back to re-resolving the tenant directly from request
headers* when the task-local is absent. So if tenancy_middleware ever
stopped scoping CURRENT_TENANT for this route, the extractor would still
independently resolve "tenant-a-sentinel" from the x-tenant-id header, the
previous check would pass, and the test would remain vacuous exactly the
way the second round worried about — just one layer deeper.

Fixed by reading CURRENT_TENANT directly in the handler instead of going
through the Tenant extractor at all:

    let ambient = CURRENT_TENANT.try_with(Clone::clone).ok().flatten();
    if ambient.as_deref() != Some("tenant-a-sentinel") { ...500... }

Verified non-vacuous by simulating exactly the scenario Codex named:
temporarily edited tenancy_middleware (autumn/src/tenancy.rs) to stop
scoping CURRENT_TENANT while leaving tenant *resolution* (header parsing)
fully intact —

    let _ = &tenant_id;
    let response = crate::tenant_cell::CURRENT_TENANT_CELL
        .scope(Some(handle), next.run(request))
        .await;

Reran the test with this in place. Result: FAILED, on exactly the new
precondition check:

    assertion `left == right` failed: expected 200 OK, got 500 Internal Server Error.
    Body: {...,"detail":"Internal server error",...}

This confirms the new check catches the middleware-stops-scoping scenario
even though tenant *resolution* from headers would have kept working (the
exact gap the old Tenant-extractor-based check missed). Reverted
immediately after (git diff -- autumn/src/tenancy.rs empty afterward).
