Revision history:

1. Initial commit had 2 tests (X-Forwarded-For only), neither holding
   `autumn_web::security::TEST_LOCK` around the process-wide throttle
   registry. Codex review (comment 4056862993, P1) correctly flagged this as
   a real cross-test flakiness risk under `cargo test --workspace`'s full
   parallelism: a sibling throttle test's `__throttle_registry_reset()` could
   clear this test's bucket entry mid-run. Fixed by adopting the established
   `TEST_LOCK`-then-reset-then-hold-through-assertions idiom from
   `throttle_route.rs`.

2. Codex review (comment 4056862994, P2) correctly flagged that both tests
   resolved the caller only through `X-Forwarded-For` header forwarding
   (`trust_forwarded_headers = true`), so removing `apply_replay_extensions`'s
   separate `ConnectInfo(ctx.peer)` propagation — the mechanism a
   default-config app (no `trust_forwarded_headers`, the common case)
   actually depends on — would leave both tests green. Added a third test,
   `throttle_denies_the_mcp_call_via_default_config_connect_info`, that
   builds a raw request with `ConnectInfo` inserted directly (the
   `security/rate_limit_xff_bypass.rs` pattern) against default config with
   no forwarded-header trust and no XFF header, isolating that second
   mechanism. All 3 tests above are the result after both fixes; see commit
   history on the PR for the pre-fix version Codex reviewed.
