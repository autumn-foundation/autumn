# Native HTML Can Close Autumn's Widget Gaps

Autumn ships about 30 server-rendered widget concepts across three layers: changeset-bound form helpers in `form.rs`, typed accessible primitives in `a11y.rs` that will not compile without a label, and htmx widgets in `widgets.rs`. All of them are CSP-safe (no inline script, no inline `style=`) and nearly all of them work without JavaScript. Measured against the 35 universal-tier components that at least five of the six major styled suites (shadcn/ui, MUI, Ant Design, Mantine, Chakra, Bootstrap) ship, **Autumn has 11 present, 11 partial and 13 absent**. The absences cluster in four places: the floating layer (popover, tooltip, drawer, menus with real menu semantics), disclosure (accordion), rich inputs (switch, slider, styled select, multi-select, a real date picker) and loading states (spinner, skeleton). The deeper problems cut across widgets rather than sitting in any one of them. Theming is light-only with about 18 tokens and no density axis. Tabs, the combobox and the nav dropdown open and close but have no WAI-ARIA APG keyboard model. Form helpers take no hint, placeholder or attribute passthrough. The urlencoded decoder rejects repeated keys, which blocks every multi-value control. Nothing tests widget behaviour in a browser, with axe, or visually. Autumn also leads its peers in places they do not compete: an unlabeled field fails to compile, CI fails when a widget has no story, its SVG charts are accessible and script-free, and its workflow widgets (bulk actions, state transitions, reactions, comments, nested forms, wizard, infinite feed) appear in no styled suite. The 2025–26 web platform changes the cost of the no-JS contract. Invoker commands, the `popover` attribute, CSS anchor positioning (Baseline January 2026), `<details name>` and customizable `<select>` make most of the missing baseline buildable with zero JavaScript. The recommended roadmap is therefore foundations first (multi-value decoding, a richer field wrapper, dark-mode tokens, one shared keyboard module, browser and axe gates), then native-first universal widgets, then free versions of the combobox, date picker and data table that peers sell as paid tiers.

## Autumn ships about 30 widgets on three layers

The display layer lives in `autumn_web::widgets`. There are about 35 public render functions, each `#[cfg(feature = "maud")]` and returning `maud::Markup`, and the module doc promises they are composable, CSP-safe and HTML-escaping ([widgets.rs:1-103](../../../autumn/src/widgets.rs)). The layout pieces are `card` with header-action and footer slots, `stat_card`, `hero`, and `property_list` (a `<dl>` for record details). Navigation is covered by `nav_link` with segment-aware prefix matching, a `nav_bar` that has horizontal and sidebar layouts and a dropdown disclosure, `breadcrumb`, `locale_switcher`, CSS-`:target` `tabs`, and offset plus cursor `pagination_nav` ([widgets.rs:2517-3195](../../../autumn/src/widgets.rs); [pagination.rs:316-382](../../../autumn/src/ui/pagination.rs)). Feedback means `alert`, `error_summary`, an out-of-band `toast` system, `flash_messages`, and a native-`<dialog>` `modal` and `confirm_action`. Data display means `data_table` with server-side sort and `aria-sort`, `badge`, `avatar` and three SVG chart types. On top of that sits a social and workflow set that has no counterpart in shadcn or MUI: `reaction_controls`, `comment_thread`, `transition_controls`, bulk actions and `infinite_feed` ([widgets.rs:720-1860, 2213-2515, 5200-5508](../../../autumn/src/widgets.rs)).

Form controls are layered differently. **The changeset helpers cover nine control kinds**: text, password, textarea, checkbox, number, date, datetime-local, select and file. Each pre-fills its value from a `Changeset<T>` and emits `<label for>`, `aria-invalid`, `aria-describedby` and a `role="alert"` error block ([form.rs:1438-1532, 3256-3297](../../../autumn/src/form.rs)). The second layer is a set of typed primitives (`TextField`, `TextArea`, `Select`, `Checkbox`, `FileField`, `RadioGroup`) that use a `NoLabel`/`Labeled` typestate, so "an unlabeled field is therefore unrepresentable as markup" ([a11y.rs:30-73](../../../autumn/src/a11y.rs)). The third layer is the htmx widgets: `active_search`, a server-filtered `autocomplete_input` combobox, a Markdown `rich_text_area` with live preview, nested-form rows, a wizard stepper, submit tokens and CAPTCHA ([widgets.rs:105-660](../../../autumn/src/widgets.rs); [nested_form.rs:1-116](../../../autumn/src/nested_form.rs); [wizard.rs:403-450](../../../autumn/src/wizard.rs)). `form_for` dispatches a `#[model]`-derived `FormModel` across a closed, `#[non_exhaustive]` `FieldControl` enum, which works much like Django's ModelForm ([form.rs:3495-3660](../../../autumn/src/form.rs)).

Client behaviour runs on vendored htmx 2.0.4 plus **one 267-line same-origin `autumn-widgets.js`**. That file handles autocomplete selection, the min-length guard, nav toggles, the modal's invoker-commands fallback and a `closedby="any"` backdrop polyfill. There is no Alpine- or Stimulus-style state layer ([htmx.rs:37-159](../../../autumn/src/htmx.rs); [autumn-widgets.js](../../../autumn/vendor/autumn-widgets.js)). Most widgets landed in 0.6.0 (2026-07-18) and 0.7.0 (2026-08-23). 0.8.0 (2026-10-01) namespaced the classes under `autumn-*`, and the unreleased fragments hold only accessibility polish ([CHANGELOG.md](../../../CHANGELOG.md); [changelog.d/](../../../changelog.d/)). No plan in `docs/plans/` and no open GitHub issue proposes a popover, accordion, drawer, date picker or dark mode. The only open UI issue is #2666, which concerns empty accessible names. Every gap below is therefore unticketed new work.

## Gap matrix: 13 of 35 universal components are absent

The tiers combine three independent baselines. **Suite tier** counts how many of the six styled suites ship the component: universal (U) is 5–6, common (C) is 3–4, niche (N) is 1–2 ([styled-suite matrix built from shadcn](https://ui.shadcn.com/docs/components), [MUI](https://mui.com/material-ui/all-components/), [AntD](https://ant.design/components/overview), [Mantine](https://mantine.dev/llms.txt), [Chakra](https://chakra-ui.com/docs/components/concepts/overview) and [Bootstrap 5.3](https://getbootstrap.com/docs/5.3/getting-started/introduction/) navs). **Headless** counts the headless libraries out of five (Radix, React Aria, Headless UI, Base UI, Ark/Zag) that ship a dedicated primitive ([Radix packages](https://github.com/radix-ui/primitives/tree/main/packages/react); [React Aria src](https://github.com/adobe/react-spectrum/tree/main/packages/react-aria-components/src); [Headless UI](https://headlessui.com/); [Base UI](https://base-ui.com/react/overview/quick-start); [Zag](https://zagjs.com/overview/introduction)). **Peer** marks whether the component sits in the roughly 30-component core that at least eight server-rendered peers share ("Core") or in the advanced tier that peers often paywall ("Adv"). The peer set is Petal, SaladUI, RubyUI, Flux, Basecoat, shadcn-templ, maud-ui, Dioxus Components, Thaw, Web Awesome, daisyUI and Primer ([e.g. Basecoat](https://github.com/hunvreus/basecoat/tree/main/src/css/components), [shadcn-templ](https://github.com/templui/templui/tree/main/components), [maud-ui](https://docs.rs/crate/maud-ui/latest)). ## Five cross-cutting gaps matter more than any single widget

### Theming stops at 18 light-mode tokens

`tokens.css` defines about 18 custom properties: colors, `--radius`, `--shadow` and `--font-family`. It has **no spacing, type-scale, z-index or breakpoint tokens**, and the source says outright that "the token set is light-mode only" ([tokens.css:1-20](../../../autumn/src/ui/tokens.css); [tokens.rs:6-7](../../../autumn/src/ui/tokens.rs)). The 1,868-line `widgets.css` has no `prefers-color-scheme` rule. No widget except avatar has size or density variants. Class naming is also inconsistent despite the 0.8.0 rename: alert and badge roots stay unprefixed (`alert`, `badge badge--*`) and the wizard uses `wizard-*` ([CHANGELOG.md:52-62](../../../CHANGELOG.md)). The admin plugin ships its own duplicated `tokens.css` with extra aliases ([autumn-admin-plugin tokens.css](../../../autumn-admin-plugin/src/tokens.css)). Peers moved past this some time ago. All six styled suites are CSS-variable based with a dark mode ([MUI](https://mui.com/material-ui/llms.txt); [AntD](https://ant.design/docs/react/customize-theme.md)). Phoenix 1.8 generates light and dark themes and a toggle in every new app ([Phoenix 1.8 release](https://www.phoenixframework.org/blog/phoenix-1-8-released)). maud-ui, the closest Rust peer, exposes `data-theme`, `data-brand` and `data-density` (compact, comfortable, spacious) ([maud-ui](https://docs.rs/crate/maud-ui/latest)). Bootstrap 6 alpha switched to `light-dark()` and runtime token maps ([Bootstrap 6 alpha](https://blog.getbootstrap.com/2026/10/08/bootstrap-6-alpha/)). `light-dark()` suits Autumn particularly well because it switches schemes without JavaScript. On density, Autumn sits in the majority: only AntD treats density as a first-class theme algorithm (`compactAlgorithm`), while the rest use per-component size props ([AntD theme](https://ant.design/docs/react/customize-theme.md)).

### Widgets open and close but cannot be driven by keyboard

The APG contract has two halves. The first is **open, close, layer, dismiss and restore focus**, and the native platform now handles it. The second is the **in-widget keyboard model**: one Tab stop with roving focus or `aria-activedescendant`, Home/End, typeahead and ARIA state sync ([APG patterns](https://www.w3.org/WAI/ARIA/apg/patterns/)). Autumn's modal gets the first half free from `showModal()`. Its other interactive widgets fall short on the second. Tabs are `<a>` links with no arrow keys, and the docs accept that "a screen reader always hears the first tab announced as 'selected'" ([widgets.rs:4243-4258](../../../autumn/src/widgets.rs)). The autocomplete renders `role="combobox"` but has no ArrowUp/ArrowDown, no `aria-activedescendant` and a permanently false `aria-expanded`, which the APG combobox pattern requires ([APG Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)). The nav dropdown handles only Escape and click-outside. The other half of the headless libraries' value is the factoring underneath: Radix ships `roving-focus`, `focus-scope`, `dismissable-layer` and `collection` as reusable packages, and shadcn-templ carries `use_list_navigation.js`, `use_typeahead.js` and `use_dismiss.js` for the same reason ([Radix packages](https://github.com/radix-ui/primitives/tree/main/packages/react); [templui](https://github.com/templui/templui)). One shared roving-focus and typeahead module would serve about eight of the 30 APG patterns (combobox popup, listbox, menu, menubar, tabs, toolbar, tree and grid). That makes it the highest-leverage piece of JavaScript Autumn could add. Every peer that gets keyboard access right ships some version of it.

### Form helpers cannot take a hint, a placeholder or a second value

Each changeset helper's signature is just `(changeset, field, label[, step | options])`. None of them accepts a placeholder, hint, `disabled`, `readonly`, `autocomplete`, `inputmode`, `pattern`, `min`/`max` or arbitrary attributes ([form.rs:1449-3121](../../../autumn/src/form.rs)). Password, textarea and checkbox have no `required_*` variant. `required_text_input` drops the `autumn-field*` classes. No helper renders a visual required marker. Inline htmx validation exists only for text fields ([forms.md:118-126](../../../docs/guide/forms.md); [scaffold.rs:9784-9790](../../../autumn-cli/src/generate/scaffold.rs)). Phoenix's `<.input>` and Flux's `field`/`description`/`error` stubs both treat the field wrapper as the framework-owned component ([Phoenix core_components](https://github.com/phoenixframework/phoenix/blob/main/installer/templates/phx_web/components/core_components.ex.eex); [Flux stubs](https://github.com/livewire/flux/tree/main/stubs/resources/views/flux)). Autumn's wrapper has the stronger accessibility guarantees but a thinner surface.

The more fundamental blocker is decoding. `ChangesetForm` decodes through `serde_urlencoded`, and the checkbox docs note that it **"rejects duplicate keys"**. A `Vec<T>` from repeated `name=` fields therefore cannot reach a changeset ([form.rs:993-1018, 2400-2410](../../../autumn/src/form.rs)). Bulk selection already works around this with a generated `parse_bulk_ids`. Checkbox groups, `<select multiple>`, tag inputs and a multi-value combobox all hit the same wall. Multipart decoding also silently discards file fields inside `ChangesetForm` ([forms.md:793-817](../../../docs/guide/forms.md)). Nothing in the multi-value input row of the matrix is buildable until this is fixed.

### Composition is consistent in shape and uneven in detail

Every widget is a free function returning `Markup`. Optional settings go through `XConfig` builders, and children arrive as `Markup` arguments that act as slots. That is a sound model for maud. The details vary, though. Some configs borrow (`CardConfig<'a>`) and others own (`NavBarConfig`). `tabs`, `property_list` and the charts take tuple slices instead of structs. `stat_card` and `modal_trigger` are positional with no config, and the `_with` pairs follow no single rule ([widgets.rs:131-3640](../../../autumn/src/widgets.rs)). The typed a11y primitives use a third style, typestate builders that implement `Render` ([a11y.rs:515-625](../../../autumn/src/a11y.rs)). There is no element override or `asChild` equivalent, so changing a widget's inner structure means hand-writing its HTML. A modest fix is to standardize on owned builders that implement `Render`, accept an `attrs` passthrough (the role django-cotton's `{{ attrs }}` plays), and keep `Markup` slots. A render-prop system is not needed. The admin plugin is a signal that the API falls short today: it reuses `card`, `nav_bar`, `modal`, `confirm_action` and `pagination_nav`, but keeps its own table, badges, 141-line select-all script and tokens ([templates.rs:10-17](../../../autumn-admin-plugin/src/templates.rs); [admin.js](../../../autumn-admin-plugin/src/admin.js)).

### Rendering is tested exhaustively, but behaviour is not tested

The widgets have **236 unit tests in `widgets.rs`** plus per-widget integration files, such as 43 for the modal and 60 for the search widgets. A story gallery at `/_stories` holds 26 stories and has a CI gate: every story must render balanced HTML, and every top-level `pub fn` in `widgets.rs` must appear in some story ([stories.rs:1-360](../../../autumn/tests/integration/stories.rs)). CSS coverage tests check that every emitted class has a rule. Nothing exercises `autumn-widgets.js` in a browser, though. The Chromium harness behind `system-tests` contains no widget names, no axe or pa11y run exists in CI, and there is no visual regression testing ([system_test.rs](../../../autumn/src/system_test.rs); [accessibility.md:290-475](../../../docs/guide/accessibility.md)). Pagination, flash, the wizard and the a11y primitives have no stories. Peers set a higher bar here. Primer runs a dedicated `test-accessibility.yml` workflow ([Primer](https://github.com/primer/view_components/blob/main/.github/workflows/test-accessibility.yml)). Dioxus Components ships Playwright specs for each component ([DioxusLabs playwright](https://github.com/DioxusLabs/components/tree/main/playwright)). shadcn-templ runs `a11y.mjs` and `behavior.mjs` parity scripts against a live htmx server ([templui parity](https://github.com/templui/templui/tree/main/parity)). Mantine claims jest-axe on every interactive component plus more than 10,000 unit tests ([Mantine a11y](https://mantine.dev/llms/q-are-mantine-components-accessible.md)). The keyboard gaps described above exist largely because no test can see them.

## Autumn already leads where peers do not compete

Several of Autumn's guarantees have no equivalent anywhere in the peer set. **An unlabeled form field is a compile error**: the typestate primitives carry a trybuild proof, and `autumn a11y verify` plus `autumn check --a11y` lint raw `html!` with route attribution ([a11y.rs:1-73](../../../autumn/src/a11y.rs); [accessibility.md:597-760](../../../docs/guide/accessibility.md)). The styled suites check accessibility in tests, but none of the libraries surveyed makes a missing label unrepresentable. **The no-JS contract is applied per widget, not just stated.** Active search has a `<noscript>` form, autocomplete a `<noscript><select>`, `confirm_action` an unconfirmed submit, tabs fall back to `:target`, the feed to an `<a href>` sentinel, and alerts dismiss with CSS ([widgets.rs:96-103, 4180-4228](../../../autumn/src/widgets.rs)). Compare daisyUI's classic CSS-only dropdown, which relies on a `tabindex` trick that commentators say still needs JS for accessibility ([studyraid](https://app.studyraid.com/en/read/12415/400835/creating-dropdown-menus)). **CSP safety extends to styling**: per-name avatar colors are palette classes rather than `style=`, so they survive a nonce-based policy ([widgets.rs:4660-4697](../../../autumn/src/widgets.rs)).

Autumn is also early on the platform. Its modal already uses invoker commands and `closedby` with a polyfill. Bootstrap only moved to native `<dialog>` in its October 2026 alpha ([Bootstrap 6 alpha](https://blog.getbootstrap.com/2026/10/08/bootstrap-6-alpha/)), and maud-ui still files Dialog under "requires JS" ([maud-ui](https://docs.rs/crate/maud-ui/latest)). The charts are inline SVG with `role="img"`, `<title>`/`<desc>` and an optional visually hidden data table, with no script ([widgets.rs:5786-5815](../../../autumn/src/widgets.rs)). Mishka Chelekom and maud-ui delegate charts to Chart.js, ECharts or AG Grid shells instead ([Mishka JS](https://github.com/mishka-group/mishka_chelekom/tree/master/priv/assets/js)). The story gallery's "every public widget needs a story" CI gate is an anti-rot rule this research did not find in any peer catalog, Lookbook and Phoenix Storybook included, and maud-ui is the only other Rust/maud project with a gallery at all ([Lookbook](https://github.com/lookbook-hq/lookbook); [Phoenix Storybook](https://github.com/phenixdigital/phoenix_storybook)).

The workflow widgets are a real differentiator. `bulk_actions_toolbar` corresponds to the niche Action Bar that only Chakra and Mantine ship. `infinite_feed` implements the APG Feed pattern, which **none of the five headless libraries implements** ([APG Feed](https://www.w3.org/WAI/ARIA/apg/patterns/feed/)). Nested-form rows that add without JS, a session-backed wizard, `transition_controls` bound to a state machine, reactions, comment threads, submit tokens and an equal-weight consent banner all compete with Filament's Repeater and Wizard rather than with shadcn ([Filament forms](https://github.com/filamentphp/filament/tree/5.x/packages/forms/src/Components)). On form binding, the one component every server framework owns, Autumn has changeset pre-fill, htmx per-field validation, and a DSL constraint that emits both a `#[validate]` rule and the matching HTML5 attribute ([dsl.rs:18-38](../../../autumn-cli/src/generate/dsl.rs)). As a framework-shipped set, Autumn's roughly 30 concepts already exceed Phoenix 1.8's seven core components and Loco's zero ([Phoenix core_components](https://github.com/phoenixframework/phoenix/blob/main/installer/templates/phx_web/components/core_components.ex.eex); [Loco scaffold](https://github.com/loco-rs/loco/tree/master/loco-gen/src/templates/scaffold)).

## Native primitives make a no-JS roadmap feasible in 2026

The reason to act now is that the platform has absorbed the toggle-state JavaScript htmx apps used to borrow from Alpine. The table below lists what Autumn can rely on as of October 2026.

| Native feature | Status (Oct 2026) | Autumn use |
|---|---|---|
| Invoker commands (`commandfor`/`command`) | Baseline Dec 2025: Chrome 135, Firefox 144, Safari 26.2 ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Invoker_Commands_API); [web.dev](https://web.dev/blog/web-platform-12-2025)) | Already used by the modal. Extend to popover, drawer and menus |
| `popover` + `popovertarget` | Baseline 2024 ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API)) | Popover, dropdown menu, toast top layer (`popover="manual"`). Light dismiss and Escape come free |
| CSS anchor positioning | Baseline Jan 2026: Firefox 147, Chrome 125, Safari 26 ([web.dev](https://web.dev/blog/web-platform-01-2026)) | Placement and flipping for tooltips, menus and combobox popups, with no Floating UI. Safari 27 changed the `position-anchor` default ([WebKit 27](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)) |
| `<details name>` | Baseline 2024 ([MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/details)) | Accordion and collapsible with zero JS |
| `field-sizing: content` | All three engines by mid-2026 ([caniuse](https://caniuse.com/mdn-css_properties_field-sizing_content)) | Auto-growing textarea |
| `:user-invalid` | Baseline 2023 ([MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/:user-invalid)) | Post-interaction error styling |
| Same-document view transitions | Baseline Oct 2025 ([web.dev](https://web.dev/blog/same-document-view-transitions-are-now-baseline-newly-available)) | Animated htmx swaps |
| Customizable `<select>` (`base-select`) | Chrome 135+, Safari 27; Firefox behind a flag ([WebKit 27](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/)) | Styled select as progressive enhancement; it degrades to a plain select ([WebKit golden rule](https://webkit.org/blog/18117/the-golden-rule-of-customizable-select/)) |
| `<dialog closedby>` | Chrome 134, Firefox 141; not Safari ([MDN](https://developer.mozilla.org/docs/Web/API/HTMLDialogElement/closedBy)) | Light-dismiss drawer. Autumn's existing polyfill covers Safari |
| `interestfor` + `popover="hint"` | Chromium only / Chrome and Firefox 149 ([caniuse](https://caniuse.com/wf-interest-invokers); [web-features](https://web-platform-dx.github.io/web-features-explorer/features/popover-hint/)) | Tooltip and hover-card enhancement only, never the baseline |

The platform still does not provide the in-widget keyboard model (roving focus, typeahead, grid and tree navigation), an editable filtering combobox, multi-thumb sliders or a calendar grid ([APG patterns](https://www.w3.org/WAI/ARIA/apg/patterns/)). The peer-consistent design for those is what Basecoat, shadcn-templ and maud-ui converged on: small vanilla controllers bound by `data-*` attributes, re-initialised after htmx swaps, on top of a shared positioning, dismiss and list-navigation layer, with no Alpine or Stimulus ([Basecoat dropdown-menu.js](https://github.com/hunvreus/basecoat/blob/main/src/js/dropdown-menu.js); [templui](https://github.com/templui/templui)). Autumn's single `autumn-widgets.js` with its `htmx:afterSwap` re-init is already this shape. It needs a shared core, not a new architecture.

Two strategic choices sit underneath this table. First, Autumn should not chase component counts. Phoenix 1.8 deliberately cut its core set because generated components "would often get in the way of experienced developers" ([Phoenix 1.8 release](https://www.phoenixframework.org/blog/phoenix-1-8-released)). Phases 0–1 reach the roughly 30-component peer baseline without approaching maud-ui's 84. Second, maud-ui is the direct competitor and a benchmark to study: it is MIT-licensed, built on maud and htmx, and organised into pure-HTML, JS-enhanced and JS-required tiers ([maud-ui](https://github.com/hgeldenhuys/maud-ui)). It is not a drop-in, though. Autumn's changeset binding, typestate labels and per-widget no-JS fallbacks would not survive a wholesale adoption, and several components maud-ui files under "requires JS" (Dialog, Popover, Drawer, Select) are things Autumn can now ship with zero JS. Adopting shadcn-style names (Popover, Sheet, Collapsible) also lowers the learning cost, because every Phoenix, Rails, Go and Rust port now uses that vocabulary.

Several uncertainties remain. Support data for the long-settled features (`<dialog>`, `popover`, `<details name>`, `inert`, `:user-invalid`) comes from MDN and caniuse and was not re-fetched in this research. Whether Safari 27 ships `closedby` is unclear. The widget CSS and screen-reader behaviour were read from source, not observed in a browser. The GitHub scan covered three pages of open issues only, so a closed or labelled request for one of these widgets could exist.

## Conclusion

Autumn's widget gap is less a missing-components problem than a missing-infrastructure problem. Four foundations sit under most of the absent widgets: a repeated-key decoder, a field wrapper that accepts attributes, a dark-capable token set, and one keyboard module. With those in place, the universal tier reduces to thin maud wrappers over `<details>`, `popover`, `<dialog>` and anchor positioning. In 2026 the no-JS contract became an advantage rather than a tax: the features that once forced htmx apps into Alpine are now Baseline HTML, and Autumn already holds the accessibility guarantees that peers retrofit through test suites.

The competitive opening is specific. Every server-rendered peer either paywalls or delegates the combobox, date picker and data table, and none of them makes accessibility a compile-time property. A free, keyboard-complete, works-without-JS version of those three advanced widgets, verified by an axe-and-keyboard browser gate run over `/_stories`, would make Autumn the reference implementation for hypermedia component libraries in any language, not just in Rust.
