# Migrating from Autumn `0.10` to `0.11`

This guide covers everything an application, plugin, or library on
`autumn-web 0.10.x` needs to move to `0.11.0`. For the full commit-level picture
see the [`0.11.0` CHANGELOG entry](../../CHANGELOG.md#0110---2026-11-17); for a
narrative tour of what is new, see the
[0.11.0 release walkthrough](../releases/0.11.0.md).

## At a glance

- **Old version:** `autumn-web 0.10.x`
- **New version:** `autumn-web 0.11.0`
- **Expected upgrade effort:** moderate for an application with a
  database. Two changes reach most apps. First, `Cargo.toml`: a generated
  model or starter names `diesel-async` 0.9 (and, on SQLite,
  `libsqlite3-sys` 0.38), and both move up with `autumn-web`. Second, dates
  and times: the framework uses `jiff` instead of `chrono`, and every model
  that `autumn generate` wrote in 0.10.x has a `chrono::NaiveDateTime`
  field, which no longer compiles. Plan on editing each model, each
  hand-written query that binds a time, and each place that reads the clock
  or formats a date; see
  [Dates and times](#dates-and-times-chrono-is-replaced-by-jiff). Most of
  the other 18 breaks are structs that gained a field,
  enums that gained a variant, or modules that moved behind a default-on
  feature, and they reach only code that builds a framework type with a
  struct literal or builds with `default-features = false`. Budget a review
  pass if you **turn on `[tenancy]`** (the tenant header is no longer trusted
  by default), **write `#[edge]` handlers that read request headers**,
  **publish `#[event]` types** (events are wire contracts now), **run a SQLite fleet or
  a fleet engine plugin**, or **regenerate Kubernetes output** with
  `autumn release init`. Operators should read
  [Configuration changes](#configuration-changes) and
  [Behavior changes](#behavior-changes) before deploying: two framework
  migrations add indexes, and the media and billing loops now follow the
  process role.
- **MSRV delta:** `1.97.0` → `1.97.0` (unchanged)
- **Carried dependency majors:** `diesel 2.3 → 2.4`,
  `diesel-async 0.9 → 0.10`, `libsqlite3-sys 0.38 → 0.40` — see
  [Dependencies](#dependencies-diesel-async-010-and-libsqlite3-sys-040) and
  [Upstream dependency updates](#upstream-dependency-updates).
- **Replaced dependencies:** `chrono 0.4` and `chrono-tz` → `jiff 1.0` —
  see [Dates and times](#dates-and-times-chrono-is-replaced-by-jiff).

## Summary

`0.11.0` closes two trust gaps and makes wire contracts reach past one
process. The trust gaps are the breaks most apps should read first: with
`[tenancy] source = "header"`, any client could name its own tenant, so the
header now needs an explicit `header_trust`, and a signed-in session binds
the request to its tenant. An `#[edge]` capsule saw every request header but
three, so an identity-aware proxy's bearer assertion could reach it; only an
allowlist crosses now. Both are the safe default with a named opt-out.

Wire contracts grew from endpoints to events and outbox messages. `#[event]`
derives `WireShape`, and a `#[listener]` that reads a field the event does
not send fails the build. That is why `#[event]` refuses a payload it cannot
read. The same work adds `autumn contracts export` and `check` across
releases, protobuf and Avro exports for consumers outside the workspace,
and outbox delivery to another service.

The break that reaches the most code is in dates and times. `chrono` and
`chrono-tz` are unmaintained (RUSTSEC-2026-0543, RUSTSEC-2026-0555), so the
framework moved to `jiff` 1.0: `DateTime<Utc>` becomes `Timestamp`,
`NaiveDateTime` becomes `civil::DateTime`, and every framework API that took
or returned a `chrono` value takes or returns the `jiff` type. A `#[model]`
field typed with `chrono` fails to compile with a hint that names the
replacement. The framework's own JSON, SQLite text, ledger hashes and HTTP
dates keep their bytes.

The rest is room for new features: database boundaries with a Postgres role
and schema each (`DatabaseConfig::roles`), a fleet engine seam with memory
budgets and hard open limits (`DatabaseFleetConfig`, `FleetStats`),
role-aware background tasks (`graph::NodeKind`),
per-group deploy roles (`DeployConfig::groups`) and one Kubernetes workload
per role. Build-time work moved the `cluster` module, failure capture, the
plugin conformance harness, the runtime-config store and axum's WebSocket
code behind default-on features, and the config reader now reads a section
from a table only. Finally, `diesel` 2.4 closes RUSTSEC-2026-0459, and
dropping `chrono` and `chrono-tz` clears their two advisories.

Link to the [CHANGELOG entry](../../CHANGELOG.md#0110---2026-11-17) for the
full commit-level picture.

## Before you start

- Pin your existing version (`autumn-web = "=0.10.0"`) and commit.
- Run `cargo update` *before* the upgrade so the subsequent diff is just
  the major bump.
- Make sure your test suite is green on the old version. You will want
  the safety net.
- The toolchain does not move: 0.11.0 builds on Rust 1.97.0, as 0.10.0 did.

## Step-by-step

1. **Run `autumn upgrade`** — *before* the dependency bump. The release it
   migrates from is the one your `Cargo.toml` still records, so bumping first
   leaves nothing in range. It previews every mechanical change this release
   can apply to your own source — a per-file diff plus a count of affected
   sites — and writes nothing; re-run with `--apply` to take them. Anything it
   cannot safely rewrite is listed with `file:line` and a link to the guide
   section that explains it. 0.11.0 ships no rewrite of app code, so the run
   is a checklist of the 20 sections below.

   ```bash
   cargo install autumn-cli --version 0.11.0
   autumn upgrade            # preview
   autumn upgrade --apply    # take it
   ```

2. **Bump the dependencies** — every line that names `autumn-web`, and
   `diesel-async` (and `libsqlite3-sys` on SQLite) if your `Cargo.toml`
   names them. An app that ran `autumn generate scaffold`, or that started
   from the `cms` or `saas` starter, names `autumn-web` twice: once under
   `[dependencies]` and once under `[dev-dependencies]` with
   `test-support`. Keep each line's features. See
   [Dependencies](#dependencies-diesel-async-010-and-libsqlite3-sys-040).
   ```toml
   # Cargo.toml
   [dependencies]
   autumn-web = { version = "0.11", features = ["maud", "csv"] }
   diesel-async = { version = "0.10", features = ["postgres"] }

   [dev-dependencies]
   autumn-web = { version = "0.11", features = ["test-support"] }
   ```

3. **Move dates and times to `jiff`.** Remove `chrono` (and `chrono-tz`)
   from `[dependencies]` unless your own code keeps them, and remove
   `"chrono"` from diesel's `features`. Then change each `chrono` type in
   your models and code to its `jiff` replacement. See
   [Dates and times](#dates-and-times-chrono-is-replaced-by-jiff).

4. **Run `cargo check`.** Work through the compiler errors section by
   section using the cheat sheet below. Every change below is labelled
   `manual`.

5. **If you turn on `[tenancy]`, choose the tenant source** before you
   deploy. The default is now `"session"`, and `source = "header"` does not
   boot without `header_trust`. See
   [Tenancy](#tenancy-the-tenant-header-needs-header_trust).

6. **Run `autumn migrate`.** Two framework migrations add indexes:
   `20261112170000_add_jobs_unique_key_enqueued_index` and
   `20261115143207_add_commit_hooks_after_hook_recovery_index`. The new
   binary works without them, but each takes a short `SHARE` lock, so run
   them at a quiet time (see [Behavior changes](#behavior-changes)).

7. **Apply configuration changes** (see
   [Configuration changes](#configuration-changes)).

8. **Run the test suite.**

9. **Run the application locally** and exercise each feature at least
   once. Pay attention to the [Behavior changes](#behavior-changes)
   section.

## Breaking changes

### Dates and times: chrono is replaced by jiff

**Why:** `chrono` and `chrono-tz` carry RUSTSEC "unmaintained" advisories
(RUSTSEC-2026-0543 for `chrono`, RUSTSEC-2026-0555 for `chrono-tz`), and
neither advisory has a patched release. Every crate in this repository
(the framework, its plugins, the CLI, the generators, the starters and the
examples) now uses [`jiff`](https://docs.rs/jiff/1.0.0/jiff/) 1.0 and depends
on neither crate. `deny.toml` and `deny-sqlite.toml` ban both crates, so a
local `cargo deny check bans` reports one that comes back through a feature
such as diesel's `chrono`. CI does not run the `bans` check.

**You are affected if** your app names a `chrono` or `chrono_tz` type
anywhere, or calls a framework API that takes or returns a date, a time or a
duration. That is almost every app with a database: `autumn generate model`
and `autumn generate scaffold` in 0.10.x give every model
`created_at: chrono::NaiveDateTime` (and `deleted_at` with soft delete), and
write `chrono` and diesel's `chrono` feature into `Cargo.toml`.

`autumn upgrade` cannot do this for you. Each site needs a type that only a
person can choose (an instant or a wall-clock value), and the feature that
keeps `chrono` in your build sits in your `Cargo.toml`.

#### Types and re-exports

The `chrono` re-export (`reexports::chrono`) is removed. Use
`autumn_web::reexports::jiff`, or the types `autumn_web::time` re-exports:
`Timestamp`, `SignedDuration`, `Span`, `ZonedDateTime`, `Unit`, and the
modules `civil`, `tz` and `fmt`.

| `chrono` | `jiff`, through `autumn_web::time` | Notes |
|----------|-------------------------------------|-------|
| `DateTime<Utc>` | `Timestamp` | `Copy`, `Ord`, `Hash`. Range ends at `9999-12-30T22:00:00.999999999Z`. |
| `NaiveDateTime` | `civil::DateTime` | A wall-clock date and time with no zone. |
| `NaiveDate` | `civil::Date` | |
| `NaiveTime` | `civil::Time` | Getters return `i8`, not `u32`. |
| `DateTime<Local>`, `DateTime<FixedOffset>`, `DateTime<Tz>` | `ZonedDateTime` | Its serde form adds a `[Zone]` suffix; store a `Timestamp` and a zone name instead. |
| `chrono_tz::Tz` | `tz::TimeZone` | `Clone`, not `Copy`. No constants such as `Tz::Asia__Tokyo`: use `tz::TimeZone::get("Asia/Tokyo")`. |
| `chrono::Duration`, `TimeDelta` | `SignedDuration` | |
| `Weekday::Mon` … `Weekday::Sun` | `civil::Weekday::Monday` … `civil::Weekday::Sunday` | |
| `chrono::serde::ts_seconds` | `fmt::serde::timestamp::second::required` (`#[serde(with = "autumn_web::time::fmt::serde::timestamp::second::required")]`) | Same output: integer seconds. |

| `chrono` call | Replacement |
|---------------|-------------|
| `Utc::now()` | `clock.now()` from the `Clock` extractor or `state.clock()`; with no clock in scope, `autumn_web::time::ambient_now()`. The framework's determinism lint bans `Timestamp::now()` (see below). |
| `Utc::now().naive_utc()` | `autumn_web::time::ambient_civil_utc()` |
| `ndt.and_utc()` | `tz::TimeZone::UTC.to_timestamp(dt)?` (it returns a `Result`) |
| `dt.naive_utc()` | `tz::TimeZone::UTC.to_datetime(ts)` |
| `dt.with_timezone(&tz)` | `ts.to_zoned_datetime(tz.clone())` |
| `"Asia/Tokyo".parse::<Tz>()` | `tz::TimeZone::get("Asia/Tokyo")`, or `autumn_web::time_zone::parse_iana` |
| `Duration::hours(2)`, `Duration::minutes(5)`, `Duration::seconds(30)` | `SignedDuration::from_hours(2)`, `from_mins(5)`, `from_secs(30)` |
| `Duration::from_std(d)` | `SignedDuration::try_from(d)` |
| `dt.checked_add_signed(d)` | `ts.checked_add(d)` (a `Result`, not an `Option`). `ts + d` panics on overflow. |
| `a - b` on two `DateTime`s | `a - b` on two `Timestamp`s gives a `SignedDuration`; so does `a.duration_since(b)` |
| `dt.timestamp()` | `ts.as_second()` |
| `DateTime::from_timestamp(secs, 0)` | `Timestamp::from_second(secs)` (a `Result`) |
| `NaiveDate::from_ymd_opt(y, m, d)` | `civil::Date::new(y, m, d)` (a `Result`), or `civil::date(y, m, d)` for a literal |
| `NaiveDateTime::parse_from_str(s, fmt)` | `civil::DateTime::strptime(fmt, s)`: the format comes first |
| `dt.format(fmt)` | `ts.strftime(fmt)`. For `%Z`, format a zoned value: `ts.to_zoned_datetime(tz::TimeZone::UTC).strftime(fmt)` |
| `dt.to_rfc3339()` | `autumn_web::time::compat::rfc3339(ts)`: the same bytes (`+00:00`, 0/3/6/9 fraction digits) |
| `dt.to_rfc3339_opts(SecondsFormat::Secs, true)` | `compat::rfc3339_opts(ts, compat::Digits::Secs, true)` (also `Millis`, `Micros`, `AutoSi`) |
| `dt.to_rfc2822()` | `compat::rfc2822(ts)` |
| `DateTime::<Utc>::MAX_UTC`, `MIN_UTC`, `UNIX_EPOCH` | `Timestamp::MAX`, `Timestamp::MIN`, `Timestamp::UNIX_EPOCH` |
| `NaiveDateTime::default()` (1970-01-01) | build the value you mean, for example `civil::date(1970, 1, 1).at(0, 0, 0, 0)`. `civil::DateTime::default()` is `0000-01-01`. |

#### The clock

`ClockSource::now`, `Clock::now`, the `Deref` target of `Clock`,
`FixedClock::at`, `TickingClock::starting_at` and `ambient_now` use
`Timestamp`. `TickingClock::advance` stops at `Timestamp::MAX` instead of
panicking. `ambient_civil_utc()` is new: the ambient clock as a UTC
`civil::DateTime`, for the timezone-naive columns generated models use.

#### `#[model]` fields and Diesel

- A `#[model]` field typed `chrono::NaiveDateTime`, `NaiveDate`,
  `NaiveTime` or `DateTime<…>`, or an `Option` of one, does not compile. The
  error names the type to use. Use `civil::DateTime`, `civil::Date`,
  `civil::Time` or `Timestamp`. The column and the database stay the same:
  no migration.
- A field whose type is written as a bare `Timestamp`, `DateTime`, `Date`
  or `Time` is read as the `jiff` type, and the macro binds it through the
  matching `Sql*` wrapper. An application type of the same name (a custom
  Diesel newtype, or `time::Date` imported as `Date`) no longer compiles
  there. Write it with its path, such as `crate::types::Date` or
  `time::Date`, and the macro leaves it alone.
- A model with a date or time column binds it through Diesel's
  `serialize_as`. A hand-written `.values(&new_row)` or `.set(&changes)` on
  such a model passes the value owned: `.values(new_row)`, `.set(changes)`.
  Encrypted columns already had this rule.
- Diesel cannot bind or load a `jiff` value directly. In a hand-written
  query, wrap it with `autumn_web::db::{SqlTimestamp, SqlDateTime, SqlDate,
  SqlTime}`, or call `.as_sql_time()` from the `autumn_web::db::AsSqlTime`
  trait. A hand-written `Queryable`, `Insertable` or `AsChangeset` struct (not
  a `#[model]`) puts `#[diesel(deserialize_as = SqlDateTime)]` or
  `#[diesel(serialize_as = SqlDateTime)]` on its field. For an `Option` field
  that loads, use `SqlNullableTimestamp`, `SqlNullableDateTime`,
  `SqlNullableDate` or `SqlNullableTime`.
- Remove diesel's `chrono` feature from your `Cargo.toml`. While any crate in
  the graph turns it on, `chrono` stays in your build and `cargo deny` still
  reports the advisory.
- A `DateTime<Local>` form field becomes a `ZonedDateTime`.

The Diesel mapping, for reference:

| Rust value | Wrapper | Postgres | SQLite |
|------------|---------|----------|--------|
| `Timestamp` | `SqlTimestamp` | `Timestamptz` | `TimestamptzSqlite` |
| `civil::DateTime` | `SqlDateTime` | `Timestamp` | `Timestamp` |
| `civil::Date` | `SqlDate` | `Date` | `Date` |
| `civil::Time` | `SqlTime` | `Time` | `Time` |
| `Option<…>` of these | `SqlNullable…` | `Nullable<…>` | `Nullable<…>` |

#### Time zones and SLAs

- `time_zone::TimeZone` and `UserTimeZone` wrap `jiff::tz::TimeZone`, which
  is `Clone` but not `Copy`. `tz()` returns `&jiff::tz::TimeZone`, and
  `iana()` returns a `&str` borrowed from the zone (empty for a zone with no
  IANA name). The `Deref` target, `TimeZoneConfig::default_tz`,
  `parse_iana`, `local_datetime`, `local_date`, `time_ago`,
  `parse_local_datetime`, `to_local_input_value`, `datetime_local_input`,
  `with_request_time_zone` and `ambient_time_zone` take or return the `jiff`
  types. The helpers take `&jiff::tz::TimeZone`.
- `sla`: `WorkingHours::new` takes two `civil::Time`.
  `BusinessCalendar::hours` takes a `civil::Weekday` (`Monday`, not `Mon`).
  `holiday` and `is_holiday` take a `civil::Date`. `BusinessCalendar::zone`
  and `Obligation::zone` take a `jiff::tz::TimeZone` and are no longer
  `const`. `home_zone()` and `time_zone()` return `Option<&TimeZone>`. The
  `ObligationZone` trait returns `Option<jiff::tz::TimeZone>`.
  `ObligationStatus.zone` is a `jiff::tz::TimeZone`. The instant fields of
  `ObligationStatus` (`started_at`, `due_at`, `met_at`, `escalated_at`,
  `resumes_at`), `SlaBreach` (`started_at`, `due_at`, `escalated_at`) and
  `ObligationRecord` (`escalated_at`, `due_at`) are `Timestamp`. An
  obligation with no deadline is stored as `Timestamp::MAX`
  (`9999-12-30T22:00:00.999999999Z`), not `9999-12-31T23:59:59Z`; a row
  stored with the old value reads back as `Timestamp::MAX`.

#### Simulation

`Sim::advance_to` takes `impl Into<Timestamp>`, and
`Sim::advance_to_local(civil::DateTime, &tz::TimeZone)` replaces the
version generic over a `chrono` zone. `Sim::step_replica_clock` and
`ReplicaClock::offset` use `SignedDuration`. `FiredFault.at` is a
`Timestamp`.

#### Jobs

`job::enqueue_at`, `enqueue_at_on_conn`, `enqueue_at_after_commit` and the
`enqueue_at(when)` method `#[job]` generates take a `Timestamp`.
`TrackedJobRecord.updated_at` is a `Timestamp`.

#### Repository, ledger, version history and records

- Ledger: `LedgerAsOf::{transaction, valid, bitemporal}`, the
  the `ledger_as_of(record_id, at)` and `ledger_diff(record_id, from, to)`
  methods `#[repository]` generates,
  `truncate_to_micros`, `parse_sqlite_instant` and the `LedgerValidTimeValue`
  impls use `Timestamp` and `civil::DateTime`. A `cursor_key_type` names a
  `jiff` type. A grouped aggregate returns `Vec<(civil::DateTime, i64)>`.
  `DisplayTopicField` is implemented for the `jiff` types instead of the
  `chrono` types.
- Version history: `VersionEntry.recorded_at`, `VersionFilter`'s `from` and
  `to`, and `VersionFilter::between` use `Timestamp`.
- These are `Timestamp` too: outbox `created_at` and `dead_at`,
  `WebhookDeliveryLog.timestamp`, `sync::protocol::Change.updated_at`,
  notification `read_at` and `created_at`, `AuditEvent.timestamp` and
  `purge_before`, `Alert.timestamp` and `on_trigger`, `hooks`
  `MutationContext.now`, `ApiVersion` `deprecated_at` and `sunset_at`, and
  `fake::recent_datetime`. `commentable` `Comment.created_at` is a
  `civil::DateTime`.

#### Fleet, replication, capsules and MCP tasks

`fleet_tombstones::Tombstone` (its fields, `new`, `is_due` and
`after_failure`), the fleet generation and sweeper records,
`fleet_replication` (`replicated_through` and the purge paths),
`FleetLake::as_of`, and the replication status and restore-plan fields
(the restore `target` is an `Option<Timestamp>`) use `Timestamp`. `capsule::Capsule.captured_at`, its `clock: Vec<Timestamp>`,
`ReplayClock::new`, `record_clock` and `clock_readings` use `Timestamp`.
The `mcp::tasks::TaskStore` methods take `now: Timestamp`.

#### HTTP, feeds and forms

- `feed::Feed::updated`, `Feed::last_updated`, `FeedEntry::published` and
  `FeedEntry::updated` use `Timestamp`. A feed clamps at `Timestamp::MAX`.
- `etag::IntoETag` is implemented for `(civil::DateTime, i64)` and
  `(civil::DateTime, i32)`. `FreshWhen::last_modified` takes
  `impl Into<Option<Timestamp>>`.
- `format::time_ago_in_words` and `format::format_datetime` take a
  `Timestamp`. `format_datetime` with a pattern `jiff` cannot format returns
  the RFC 3339 text instead of panicking.
- `form`: `deserialize_datetime_local_utc` and its `_option` form return
  `Timestamp`; `deserialize_datetime_local_local` and its `_option` form
  return a `ZonedDateTime` in the system zone; and
  `deserialize_naive_datetime_local` and its `_option` form return
  `civil::DateTime`. The names did not change. `OpenApiSchema` and
  `SearchTextValue` are implemented for the `jiff` types instead of the
  `chrono` types.

#### Auth

`VerifiedToken.expires_at`, `TokenMetadata.expires_at` and
`IssueTokenSpec.expires_at` are `Option<Timestamp>`.
`auth::remember::RememberRecord` uses `Timestamp`.
`default_rotation_grace()` returns a `SignedDuration`, and
`evaluate_remember` takes `now: Timestamp` and `grace: SignedDuration`.

#### Generators

- `autumn generate model` and `autumn generate scaffold` write
  `created_at: autumn_web::time::civil::DateTime` (and `deleted_at:
  Option<autumn_web::time::civil::DateTime>` with soft delete). They no
  longer add `chrono` or diesel's `chrono` feature to `Cargo.toml`. A model
  generated into an upgraded app needs no `chrono`; the models generated
  before keep their `chrono` fields until you change them.
- The field DSL accepts `Timestamp` (an instant),
  `CivilDateTime` (`civil::DateTime`) and `Date` (`civil::Date`). The old
  spellings still work and give the `jiff` types: `DateTime` gives
  `Timestamp`, `NaiveDateTime` gives `civil::DateTime`, `NaiveDate` and
  `date` give `civil::Date`, and `time`, `Time` and `NaiveTime` give
  `civil::Time`.

#### Output that changes

Code that compiles can still print or send different text. See
[Behavior changes](#behavior-changes) for the list: `Display`, the serde
fraction digits of a model field, `civil::DateTime::default()` and the end of
the `Timestamp` range.

#### Determinism lint

The framework's `clippy.toml` bans `jiff::Timestamp::now`,
`jiff::ZonedDateTime::now` and `jiff::tz::TimeZone::system` instead of
`chrono::Utc::now`. An app that copied the config adds the three entries
and drops the `chrono` one, or a direct clock read goes unflagged.

#### The common edits

**Before (`0.10`):**

```toml
[dependencies]
chrono = { version = "0.4", features = ["serde"] }
diesel = { version = "2", features = ["postgres", "chrono", "uuid"] }
```

```rust
#[autumn_web::model]
pub struct Post {
    #[id]
    pub id: i64,
    pub title: String,
    pub created_at: chrono::NaiveDateTime,
}

let post = diesel::insert_into(posts::table)
    .values(&new_post)
    .get_result::<Post>(&mut conn)
    .await?;

let cutoff = chrono::Utc::now().naive_utc() - chrono::Duration::days(30);
let recent = posts::table
    .filter(posts::created_at.gt(cutoff))
    .load::<Post>(&mut conn)
    .await?;

let label = post.created_at.format("%B %-d, %Y").to_string();
```

**After (`0.11`):**

```toml
[dependencies]
diesel = { version = "2", features = ["postgres", "uuid"] }
```

```rust
use autumn_web::db::AsSqlTime as _;
use autumn_web::time::{SignedDuration, civil};

#[autumn_web::model]
pub struct Post {
    #[id]
    pub id: i64,
    pub title: String,
    pub created_at: civil::DateTime,
}

let post = diesel::insert_into(posts::table)
    .values(new_post)
    .get_result::<Post>(&mut conn)
    .await?;

let cutoff = autumn_web::time::ambient_civil_utc() - SignedDuration::from_hours(30 * 24);
let recent = posts::table
    .filter(posts::created_at.gt(cutoff.as_sql_time()))
    .load::<Post>(&mut conn)
    .await?;

let label = post.created_at.strftime("%B %-d, %Y").to_string();
```

A handler that read `chrono::Utc::now()` takes the `Clock` extractor, so a
test can fix the time:

```rust
use autumn_web::prelude::*;
use autumn_web::time::{Clock, SignedDuration, Timestamp};

#[get("/token")]
async fn check_token(clock: Clock) -> axum::http::StatusCode {
    let issued: Timestamp = "2025-01-01T00:00:00Z".parse().unwrap();
    if clock.now() < issued + SignedDuration::from_hours(30 * 24) {
        axum::http::StatusCode::OK
    } else {
        axum::http::StatusCode::UNAUTHORIZED
    }
}
```

#### Keeping `chrono` in your own code

You can keep `chrono` for code that never touches the framework. It is then
your dependency, and `cargo deny` reports the advisory against your app.
Convert at the framework boundary, through whole seconds and nanoseconds:

```rust
use autumn_web::reexports::jiff;
use autumn_web::time::Timestamp;

/// Fails for an instant outside `jiff`'s range (years -9999 to 9999).
fn to_jiff(dt: chrono::DateTime<chrono::Utc>) -> Result<Timestamp, jiff::Error> {
    // chrono stores a leap second as a fraction of 1_000_000_000 or more.
    // jiff has no leap seconds, so keep it in the same second.
    let nanos = dt.timestamp_subsec_nanos().min(999_999_999);
    Timestamp::new(dt.timestamp(), nanos as i32)
}

fn to_chrono(ts: Timestamp) -> chrono::DateTime<chrono::Utc> {
    // Before 1970, jiff's fraction is negative (it keeps the sign of the
    // seconds). chrono wants a fraction from 0 to 999_999_999.
    let (secs, nanos) = (ts.as_second(), ts.subsec_nanosecond());
    let (secs, nanos) = if nanos < 0 {
        (secs - 1, nanos + 1_000_000_000)
    } else {
        (secs, nanos)
    };
    chrono::DateTime::from_timestamp(secs, nanos as u32)
        .expect("jiff's range fits in chrono's")
}
```

A `#[model]` field must still be a `jiff` type, and the framework APIs above
take only `jiff` types. Keep diesel's `chrono` feature only if your own
hand-written Diesel code still binds `chrono` values.

**Automation:** `manual` (registry entry `0.11.0-chrono-to-jiff`) — each
site needs a type chosen by a person, an instant or a wall-clock value, and
the `chrono` feature that keeps the crate in your build is in your own
`Cargo.toml`.

### Tenancy: the tenant header needs `header_trust`

**Why:** with `source = "header"`, any client could select its tenant. A
user of tenant A could send `x-tenant-id: B` and get tenant B's rows and
shard.

**You are affected if `[tenancy] enabled = true` and one of these is true:**
you do not set `source`; you set `source = "header"`; or the session holds
`tenancy.session_key` (default `tenant_id`) with a source other than
`session`.

- The default `source` is now `"session"`. An app that used the default
  header gets `401`, or the login redirect, until it sets `source` or
  writes the tenant to the session.
- `source = "header"` needs `header_trust`. Without it, the app does not
  start, and a router built without `run` returns `500`.
- `header_trust = "trusted_proxy"` accepts the header only from a peer
  address in `security.trusted_proxies.ranges`, and only when
  `security.trusted_proxies.trust_forwarded_headers = true` (default
  `false`). `trusted_hops` does not count. The boot fails when
  `trust_forwarded_headers` is off or no range is valid. The proxy must set
  the header and remove the client's copy.
- `header_trust = "any_client"` accepts the header from any client. It is
  unsafe. Use it only when the app checks tenant membership itself.
- With `source = "header"`, two header values get `400`.
- For every source except `session`: when the session holds
  `tenancy.session_key`, the resolved tenant must be equal to it, with the
  same case, or the request gets `403`. An empty value does not bind. An app
  that keeps another form of the id under that key (for example, a number
  for a slug subdomain) must move it to another key.
- A `TenancyConfig` struct literal needs `header_trust`, or
  `..Default::default()`.

**Before (`0.10`):**

```toml
[tenancy]
enabled = true
```

**After (`0.11`):**

Recommended: the tenant comes from the signed-in session.

```toml
[tenancy]
enabled = true
source = "session"
session_key = "tenant_id"
```

Or: a gateway sets the header after it authenticates the user.

```toml
[tenancy]
enabled = true
source = "header"
header_trust = "trusted_proxy"

[security.trusted_proxies]
trust_forwarded_headers = true
ranges = ["10.0.0.0/8"]
```

**Automation:** `manual` (registry entry `0.11.0-tenancy-header-trust`) — select the tenant source. A codemod cannot know
which source is correct for the app.

### Edge: handlers see only allowlisted request headers

**Why:** an identity-aware proxy adds a bearer assertion under its own header
name, for example `cf-access-jwt-assertion` or `x-goog-iap-jwt-assertion`.
The old denylist did not name these headers, so a capsule got them and could
echo them. Now only `autumn_edge::wire::ALLOWED_REQUEST_HEADERS` cross: content
negotiation (`accept*`), conditional requests (`if-*`), `range`,
`cache-control` and `user-agent`.

**You are affected if** your code names `SENSITIVE_HEADERS` (from
`autumn_edge` or `autumn_edge::wire`) or `strip_sensitive_headers`, or an
`#[edge]` handler reads a header that is not on the list through `HeaderMap`.
Examples: `host`, `referer`, `x-request-id`, htmx headers such as
`hx-request`, or a custom header. A handler that gives a fragment for
`hx-request` now always gives the full page.
Both lanes now drop that header. The origin middleware still sees it.

**Before (`0.10`):**

```rust
use autumn_edge::wire::{strip_sensitive_headers, SENSITIVE_HEADERS};

let safe = strip_sensitive_headers(&headers);
assert!(!SENSITIVE_HEADERS.contains(&"accept"));
```

**After (`0.11`):**

```rust

assert!(request_header_allowed("accept"));
```

**Automation:** `manual` (registry entry `0.11.0-edge-header-allowlist`) — a codemod cannot know which header a handler
needs. Move a handler that needs another header to an origin-only route.

### Events: `#[event]` derives `WireShape` and refuses what it cannot read

**Why:** an event payload is a wire contract between a producer and its
consumers. `#[event]` now records the payload's shape, so a `#[listener]`

**You are affected only if an `#[event]` type is generic, an enum, a tuple

### Deploy: `DeployConfig` has a `groups` field

**Why:** `[[deploy.groups]]` puts a role on a group of fleet hosts. The
field is empty by default. See
[Per-group roles](../guide/fleet-deploys.md#per-group-roles).

**You are affected only if your code builds a `DeployConfig` with a struct
literal and no `..Default::default()`.** TOML and `AUTUMN_*` config need no
change.

**Before (`0.10`):**

```rust,ignore
DeployConfig {
    host: Some("10.0.0.1".to_owned()),
    // ...every other field...
    bake: DeployBakeConfig::default(),
}
```

**After (`0.11`):**

```rust,ignore
DeployConfig {
    host: Some("10.0.0.1".to_owned()),
    // ...every other field...
    bake: DeployBakeConfig::default(),
    groups: Vec::new(),
}
```

**Automation:** `manual` (registry entry `0.11.0-deploy-config-groups`) — an empty list keeps the old behavior.

### Release: regenerated Kubernetes output has one workload per role

**Why:** `autumn release init --target kubernetes` now writes one workload per
role. See [One workload per role](../guide/kubernetes.md#one-workload-per-role).

**You are affected only if you run `autumn release init --target kubernetes
--force` again over an earlier output.** Files you do not regenerate keep
working.

- Object names change from `<name>` to `<name>-<role>`, for example
  `shop-combined`. An upgrade replaces the Deployment and the Service. Point
  an Ingress or a `flagger.ingressRef` outside the chart at the new Service.
- The Helm value `replicaCount` moved to `roles.<name>.replicaCount`. The
  chart refuses to render when a values file still sets `replicaCount`. Move
  the value:

  ```yaml
  # Before
  replicaCount: 5
  # After
  roles:
    combined:
      replicaCount: 5
  ```

- The Kustomize `deployment.yaml`, `service.yaml` and `pdb.yaml` moved from
  `base/` to `components/<role>/`. Change the target names in your overlay
  patches, for example `shop` to `shop-combined`.

**Automation:** `manual` (registry entry `0.11.0-release-kubernetes-per-role`) — the generator cannot see your overlays and values
files.

## Plugin authors

Everything here is addressed to someone maintaining an `autumn-plugin-*` /
`autumn-*-plugin` crate, not to an application author. See
[`docs/plugins.md`](../plugins.md#the-plugin-api-contract) for the tiers.

- **Stable surface changed:** no signature of the `Plugin` trait,
  `PluginContract` or `AppBuilder::plugin` changed.
  `autumn_web::plugin_conformance` now sits behind the default-on
  `plugin-conformance` feature: a plugin that depends on `autumn-web` with
  `default-features = false` and runs the harness in its tests names the
  feature. See
  [Features](#features-plugin-conformance-runtime-config-and-axum-ws). A
  plugin whose own code builds a `DatabaseConfig`, `DatabaseFleetConfig`,
  `OutboxConfig`, `TenancyConfig` or `DeployConfig` literal needs the same
  new field an app does.
- **Stable surface changed (dates and times):** every framework API a
  plugin passes a date, a time or a duration through now uses the `jiff`
  type, as listed in
  [Dates and times](#dates-and-times-chrono-is-replaced-by-jiff). A plugin
  that depended on `chrono` through `autumn-web` (`reexports::chrono`) now
  uses `autumn_web::time` or `autumn_web::reexports::jiff`. A plugin that
  writes JSON for clients or stores and wants chrono's fraction digits marks
  a `Timestamp` field with
  `#[serde(with = "autumn_web::time::compat::serde_autosi")]`
  (`serde_autosi_option` for an `Option`). The in-repo plugins do this, so
  their stored and wire JSON is unchanged.
- **`autumn-billing`:** `BillingStore::finish_event(event_id, now:
  Timestamp)` and `BillingStore::prune_events(before: Timestamp)` take a
  `Timestamp`, and so do the time fields of `Customer`, `Subscription`,
  `Invoice`, `DunningAttempt`, `BillingEvent`, the snapshots and the
  `CustomerUpsert`, `SubscriptionUpsert` and `InvoiceUpsert` types. A
  third-party `BillingStore` changes its signatures.
- **`autumn-media-plugin`:** `RoomStore::join_room` takes
  `token_ttl: SignedDuration`, `RoomStore::roster` takes
  `session_max: SignedDuration`, `RoomStore::heartbeat` takes both and
  returns a `Timestamp`, and `RoomStore::reap_stale` takes
  `now: Timestamp` and `idle_ttl: SignedDuration`. `renewed_expiry`,
  `RoomService::new` (`token_ttl`), `RoomService::with_session_max` and
  `RoomService::session_max` use `SignedDuration` and `Timestamp`, and so do
  the room response types. A third-party `RoomStore` changes its signatures.
- **`autumn-admin-plugin`:** `AdminHistoryEntry.recorded_at` is a
  `Timestamp`, and `ExperimentChange.changed_at` is a `civil::DateTime`. An
  `AdminModel` that builds history entries passes the `jiff` value.
- **`autumn-schema-core`:** `ColumnType::rust_type()` returns
  `"autumn_web::time::civil::DateTime"` and `"autumn_web::time::Timestamp"`
  for the two timestamp column types. `ColumnType::from_rust_type` still
  reads the `chrono` spellings, so a schema written by 0.10.x still parses.
- **Experimental surface changed:** `SlotOwnershipStore` gains
  `ensure_schema`, with a default body, so an existing store compiles
  unchanged.
- **New stable surface (background tasks, #3545):**
  `AppBuilder::background_task`, `AppBuilder::background`,
  `AppBuilder::plugin_capability` and the `background` module
  (`BackgroundTask`, `PluginCapability`, `BackgroundCapability`,
  `Role::runs_plugin`). Move a loop that you `tokio::spawn` in `on_startup`
  to `background_task`, so that `AUTUMN_ROLE=web` does not run it. A plugin
  switch such as `worker_enabled` becomes `BackgroundTask::explicit`. A loop
  in `on_startup` that you do not move behaves as before. See
  [Background work in a plugin](../guide/extensibility.md#background-work-in-a-plugin)
  and [Background tasks for plugins and apps](../guide/jobs.md#background-tasks-for-plugins-and-apps).
- **In-repo plugins on background tasks (#3546):** `autumn-media-plugin`
  and `autumn-billing` start no loop from `on_startup` now. The reference
  plugin shows the pattern: one-time setup in `on_startup`, the loop in
  `background_task`. A test in `xtask` (`plugin_spawns`) fails on a spawn
  that an `on_startup` or `state_initializer` argument of a plugin crate
  reaches. `spawn_room_reaper_loop` and `spawn_retention_sweep_loop` are
  deprecated. Call `run_room_reaper` or `run_retention_sweep` from a
  `background_task`.
- **New experimental surface (fleet engines, #3642):** `db::fleet_engine`
  (the `FleetEngine` trait and `DatabaseFleet::with_engine`) and
  `plugin_conformance::fleet` (`FleetFixture`, `run_fleet_conformance`).
  Declare them with `uses_experimental`. An engine plugin implements
  `FleetEngine` and runs the kit in its own CI. `DatabaseFleet`,
  `FleetDatabase`, `FleetLifecycle` and `BackgroundOpen` take a parameter
  `E: FleetEngine`. With `sqlite`, `E` defaults to `SqliteEngine`, so
  `SQLite` code needs no change. A handler of another engine reads
  `FleetDatabase::handle`. `FleetEngine::ship_mode` returns a `ShipMode`:
  an engine plugin returns `ShipMode::Generations { every }` (core ships
  its snapshots) or `ShipMode::Rebuild`. `ShipMode::Continuous` carries a
  sealed `ContinuousShipper` that only `SqliteEngine` uses, so `ShipMode`
  is not `Copy` or `PartialEq`: match it with `matches!`. See
  [ADR 0040](../adr/0040-fleet-engine-seams.md).
- **New experimental surface (fleet extractors):** the `fleet` module
  (`resolve`, `resolve_key`, `FleetLease`, `fleet_of`, `ownership_store`) and
  `AppBuilder::fleet_ownership_store`. Declare them with
  `uses_experimental`. An engine plugin writes its own extractor over
  `fleet::resolve::<E>` and puts its `DatabaseFleet<E>` in the app state with
  `insert_extension`. A sidecar hook ships through
  `FleetDatabase::sidecar_replica`. See
  [Writing a fleet extractor](../guide/sqlite-fleet.md#writing-a-fleet-extractor).
- **New stable surface (conformance, #2828):**
  `plugin_conformance::run_route_checks` and `RouteSource::from_wire`.
  `autumn plugin-check --plugin-name <your-plugin>` calls
  `run_route_checks`, so your conformance test and the CLI give the same
  result for the same routes.
- **Stable surface behavior (conformance, #2828):** `run_conformance` with a
  contract uses the contract's `registered_as` when no route carries the
  config name and a route carries `registered_as`. Routes under more than
  one name of the plugin fail `route-attribution`. No signature changes. A
  test that passed its crate name while the routes carry `Plugin::name()`
  now passes. Some CLI diagnostic text changes; do not match on it.
- **Declared range to move to:** each release, bump the literal in
  `Plugin::contract`'s `.autumn_web("…")` to the new series (or write it with
  `lockstep_range(env!("CARGO_PKG_VERSION"))` if the plugin releases in
  lockstep with the framework) and re-run
  `autumn plugin-check --plugin-name <your-plugin>`. The examples in the
  `Plugin::contract` and `plugin_contract` rustdoc now name `"0.11"`, the
  series 0.11.0 opens; copy the shape, not the literal. A range that
  excludes the host, such as `.autumn_web("0.10")` on 0.11.0, makes
  `AppBuilder::plugin` panic at registration unless
  `AUTUMN_PLUGIN_CONTRACT=warn` demotes it.

## Behavior changes

Changes that still compile but behave differently at runtime.

- **Tenancy:** with any source except `session`, a session that holds
  `tenancy.session_key` binds the request to that tenant. A header, host
  name or token for another tenant gets `403`. With `source = "header"`, two
  header values get `400`.
- **Edge:** an `#[edge]` handler that gave a fragment for `hx-request` now
  always gives the full page, because `hx-request` does not cross. The
  origin middleware still sees every header.
- **Framework migrations:** `20261112170000_add_jobs_unique_key_enqueued_index`
  adds a partial index to `autumn_jobs`, and
  `20261115143207_add_commit_hooks_after_hook_recovery_index` one to
  `autumn_repository_commit_hooks`. Each build takes a `SHARE` lock (about
  0.5 s and 80 ms at 1M rows), so enqueue, claim, ack and hook writes wait
  for it. The binary does not need them, so a deploy can come first.
- **Fleet:** an open under an ownership epoch refuses a database that
  records a newer epoch (`FleetError::NewerEpoch`, `421`). Before, the open
  served it. The check, the stamp and the write are one transaction. Only
  a host that lost its slot to a newer owner sees this. A control database
  made again from nothing restarts its epochs: re-import each database
  (`DatabaseFleet::import` drops the old stamp).
- **Fleet:** `/actuator/health` `db:fleet` details now include
  `resident_bytes`, `max_resident_bytes`, `peak_open`,
  `over_cap_opens_total` and `refused_total`.
- **Fleet:** the fleet core is in every `db` build, Postgres too. The `db`
  feature now pulls in `fd-lock`, which the `sqlite` feature pulled in
  before. No new crate.
- **Media and billing loops follow the role (#3546).** The `db` room reaper
  and the recording retention sweep do not run on `web`. The `memory` room
  reaper runs on `combined` and `web`, not on `worker`. The dunning re-arm
  runs on `combined` and `worker`, not on `web`. A fleet of only `web`
  replicas needs a `worker`, or `MediaPlugin::room_reaper_on_every_role()`
  and `MediaPlugin::retention_on_every_role()`. See
  [Media: background tasks and roles](../guide/media.md#background-tasks-and-roles).
- **Graph:** `autumn graph check-boundaries` checks the nodes of a renamed
  `[[bin]]` target in the boundary of its package (#3599). New violations
  can show. Fix them, or run with `--update-baseline`. A `may_read` or
  `may_write` pattern with a `*` now matches only tables in the graph
  (#3606).
- **Config:** a type error in `autumn.toml` now names the full key, for
  example ``in `server.port` ``. Before, `AutumnConfig::load` showed a line
  of the merged config, which is not a file you wrote. `load_from` errors
  also give the key, not the line. A syntax error keeps its line. A message
  parser that read the `TOML parse error at line` prefix of a type error
  must read the key instead.
- **Capacity:** a value of the wrong type in `capacity.lock` now names the
  key, for example ``in `envelope.admission_limit` ``. A `capacity.lock`
  with an integer above 9223372036854775807 does not load. Only `seed` can
  be that large, and only from an explicit `autumn calibrate --seed`. Run
  `autumn calibrate` again with a smaller seed.
- **Wire contracts:** `autumn contracts export` and `autumn contracts
  check` are new in this release. When you adopt them, a `WireShape` or
  `#[event]` field whose type is neither a `WireShape` type nor a known leaf
  (usually an enum) stops the export: mark it `#[wire(opaque)]`, or derive
  `WireShape` on a struct type. The build does not change. Type descriptor
  files under `target/autumn-contracts` now hold the module in their name:
  delete that directory once after the upgrade, so an old file does not
  change a build message.
- **Assets:** `autumn assets` keeps every read and write in `static/`. A
  manifest `file` must be a relative path with `/` separators, and `update`
  downloads only from `https` sources. A manifest that breaks a rule does
  not load. Re-add an `http` source with `add --url`.
- **Inbound mail:** the SES endpoint accepts only an SNS origin for
  `SigningCertURL` and `SubscribeURL`, refuses redirects on the certificate
  fetch, and checks the `TopicArn` before any fetch.

### Dates and times: text and JSON output

These follow from [Dates and times](#dates-and-times-chrono-is-replaced-by-jiff).
They reach code that prints or serializes a date or time itself. The
framework's own formats do not change: the JSON it stores or sends for
jobs, capsules, sync, audit, alerts, the outbox, webhooks, notifications,
billing and media rooms; ledger snapshots, commit-hook payloads and the
ledger hash; `SQLite` `TEXT` values; and HTTP dates.

- **`Display`:** a `Timestamp` prints `2024-01-01T00:00:00Z`, where
  `DateTime<Utc>` printed `2024-01-01 00:00:00 UTC`. So
  `clock.now().to_string()` changes. A `civil::DateTime` puts `T` between
  the date and the time, where `NaiveDateTime` put a space. A scaffold's CSV
  export writes the `T` and `Z` forms; its importer still reads the old
  space and `UTC` forms.
- **Serde of your own fields:** `jiff` writes the fewest fraction digits
  that hold the value (`.12`), where `chrono` wrote 0, 3, 6 or 9 (`.120`).
  The API JSON of a `#[model]` field, or of any field you changed to a
  `jiff` type, changes when the value has a fraction. To keep `chrono`'s digits on
  a `Timestamp` field, mark it
  `#[serde(with = "autumn_web::time::compat::serde_autosi")]`, or
  `serde_autosi_option` with `#[serde(default)]` for an
  `Option<Timestamp>`. There is no such adapter for `civil` values. Reading
  accepts the RFC 3339 text `chrono`'s serde wrote, with `Z` or an offset
  and a `T` or a space separator. It rejects two forms `chrono`'s relaxed
  parser took: a trailing ` UTC` (`2024-01-01 00:00:00 UTC`, `chrono`'s
  `Display` form) and a space before the offset
  (`2024-01-01T00:00:00 +00:00`). It also rejects more than nine fraction
  digits, which `chrono` dropped.
- **`ZonedDateTime` serde** adds the zone in brackets
  (`2024-01-01T09:00:00+09:00[Asia/Tokyo]`). Send a `Timestamp` to clients
  instead.
- **`civil::DateTime::default()`** is `0000-01-01T00:00:00`, where
  `NaiveDateTime::default()` was `1970-01-01 00:00:00`.
- **Range:** a `Timestamp` ends at `9999-12-30T22:00:00.999999999Z`. A
  Postgres value past it, such as the old far-future `run_at` of a job,
  reads back as `Timestamp::MAX` instead of failing. Arithmetic that would
  pass the end returns an error from `checked_add`; `+` panics.
- **Time zone names** match without case (`america/new_york` finds
  `America/New_York`); `TimeZone::iana()` gives the canonical name. Only the
  IANA database built into the binary is read, never the host's files.
- **`format::format_datetime`** with a pattern `jiff` cannot format returns
  the RFC 3339 text of the instant. Before, it panicked.
- **`cms` starter:** the site date format is checked against `jiff`'s
  `strftime` directives, which differ slightly from `chrono`'s. A saved
  format that `jiff` cannot render shows the ISO date (`2024-01-02`). The
  default, `%B %-d, %Y`, renders as before.

### Comments: the comment router shows one page (#3325)

`commentable::router` reads one page of a thread, not the whole thread. A
page holds up to 50 top-level comments and all their replies. After a post,
the response shows the page that holds the new comment.

What to do:

1. On a host page that renders a thread, call `comment_thread_page` (not
   `comment_thread`), and pass the page to the widget with
   `.page(page.after, page.next)`.
2. Read `?after=<id>` from the host page's query string, and pass it to
   `comment_thread_page`.
3. Use the same page size on the host page and in
   `CommentsConfig::page_size`. Else a no-JS post can return to a page that
   does not show the new comment.
4. Index the comments table: `(commentable_type, commentable_id, created_at,
   id) WHERE parent_id IS NULL` (add `AND deleted_at IS NULL` when the
   binding soft-deletes, the default `soft_delete = true`), and `parent_id`.

### Metrics: the `"<route> SELECT"` key is deprecated

`db_queries["<route> SELECT"]` from the `Db` extractor is not a query. It is
the time a request held its connection, from checkout to release. It includes
all statements and all other work in the hold, for example a fan-out. A route
that only writes also shows it.

This release records each hold in two places:

| Key | Status |
| --- | --- |
| `db_queries["POST /census SELECT"]` | Deprecated for holds. The next release stops the `Db` extractor writing it. |
| `db_connection_holds["POST /census"]` | New. Use this one. |

`run_instrumented` also records a real `SELECT` under `"<route> SELECT"`.
In this release, that key can mix holds and statements. After the next
release, it holds only statements.

What to do:

1. Move each dashboard and alert that reads `db_queries["<route> SELECT"]`
   for the hold to `db_connection_holds["<route>"]`. The new key has no
   verb. A `Db` from a shard adds the shard, for example
   `"GET /notes shard=shard0"`.
2. Read statement times from `db_queries`. They come only from
   `autumn_web::db::run_instrumented`. If the app does not call it,
   `db_queries` is empty after the next release.

## Troubleshooting

- **``failed to select a version for `diesel` ``.** A `Cargo.toml` line
  still names `diesel-async = "0.9"`. Move it to `0.10`; see
  [Dependencies](#dependencies-diesel-async-010-and-libsqlite3-sys-040).
- **``links to the native library `sqlite3` `` conflict.** A SQLite app still
  names `libsqlite3-sys = "0.38"`. Move it to `0.40`.
- **Two `autumn-web` versions in `cargo tree`.** One `Cargo.toml` line still
  names `0.10`. A scaffolded app has two (`[dependencies]` and
  `[dev-dependencies]`); bump both.
- **The boot stops on `[tenancy]`.** `source = "header"` needs
  `header_trust`. With `"trusted_proxy"`, set
  `security.trusted_proxies.trust_forwarded_headers = true` and give at
  least one valid range in `security.trusted_proxies.ranges`
  (`trusted_hops` does not count).
- **Every tenant request gets `401` or the login redirect.** The app used
  the old default header source. Set `source`, or write the tenant to the
  session.
- **`invalid type: sequence, expected struct …` at boot.** A config section
  is written as an array. Give each field its name.
- **`chrono` is still in `cargo tree`.** A crate turns on diesel's
  `chrono` feature, usually your own `Cargo.toml`. Run
  `cargo tree -i chrono -e features` to see which, and remove `"chrono"`
  from that crate's diesel `features`.
- **A JSON client sees `.12` where it saw `.120`.** A field moved from
  `chrono` to `jiff`. Mark a `Timestamp` field with
  `#[serde(with = "autumn_web::time::compat::serde_autosi")]`.
- **A stored value or a client payload no longer deserializes.** It holds
  a time in a form only `chrono`'s relaxed parser took: a trailing ` UTC`
  (`2024-01-01 00:00:00 UTC`) or a space before the offset. Rewrite the
  stored values as RFC 3339 (`2024-01-01T00:00:00Z`), or have the client
  send that form.
- **A test compares `to_string()` output and fails.** `Timestamp` prints
  `Z`, not ` UTC`, and `civil::DateTime` prints `T`, not a space. Use
  `autumn_web::time::compat::rfc3339` where you need `chrono`'s RFC 3339
  bytes.
- **The `db` room reaper or the retention sweep stopped.** The deployment
  runs only `web` replicas. Add a `worker`, or opt the loops into every role.
