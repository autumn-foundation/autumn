# Migrating from Autumn `0.4` to `0.5`

## At a glance

- **Old version:** `autumn-web 0.4.x`
- **New version:** `autumn-web 0.5.0`
- **Expected upgrade effort:** none for a local-only or single-process app;
  small but **mandatory** for any app served through a load balancer, reverse
  proxy or CDN — 0.5.0 fixes three forwarded-header trust CVEs and stops
  honouring `X-Forwarded-*` until you declare your proxy boundary.
- **MSRV delta:** `1.88.0` -> `1.88.0` (unchanged)
- **Carried dependency majors:** none

## Summary

0.5.0 is a large, overwhelmingly **additive** release — pagination on
`#[repository]`, the dev request inspector, soft delete, bulk CRUD, full-text
search, multi-tenancy, feature flags, idempotency keys, and much more. Existing
code keeps compiling.

The one thing that changes underneath a running app is *who you trust to tell
you the client's address*. 0.5.0 closes PR #753 (`X-Forwarded-For` rate-limit
bypass) and PR #785 / #791 (`X-Forwarded-Host` CSRF and method-override
spoofing) by replacing per-middleware trust settings with a single
`[security.trusted_proxies]` policy that every framework middleware honours —
and by defaulting `prod` to trusting **no** proxy until you configure one. If
your app sits behind a proxy and you do not configure it, nothing fails to
compile and nothing fails to boot: you simply start rate-limiting on, and
logging, the proxy's address instead of your users'.

Full commit-level picture: the [0.5.0 CHANGELOG entry](../../CHANGELOG.md).

## Before you start

1. Pin your current dependency (`autumn-web = "=0.4.0"`) and commit.
2. Make sure your tests are green on 0.4.x. You will want the safety net.
3. Write down how requests actually reach your app in production: the CIDR
   ranges of the proxies in front of it, or how many hops sit between the
   internet and your process. You need one of those two facts for the
   [trusted-proxies step](#security-forwarded-header-trust-is-now-declared-once).
4. Upgrade the Autumn crates together:

   ```toml
   [dependencies]
   autumn-web = "0.5"
   ```

## Step-by-step

1. **Bump the dependency** and run `cargo check`. For most apps this is clean.
2. **Declare your proxy boundary** — see
   [Forwarded-header trust](#security-forwarded-header-trust-is-now-declared-once).
   Skip only if nothing sits between the internet and your process.
3. **Move deprecated rate-limit proxy keys** to the new block — see
   [Deprecated configuration keys](#deprecated-configuration-keys).
4. **Replace direct `X-Forwarded-*` reads** with the new extractors — see
   [Reading client identity](#reading-client-identity-clientaddr-clienthost-clientscheme).
5. **Run the test suite**, then `autumn doctor --strict`.
6. **Run the app** and walk the [verification list](#how-to-verify).

## Breaking changes

### Security: forwarded-header trust is now declared once

**Why:** three separate middlewares each decided independently whether to
believe `X-Forwarded-*`, and an attacker who could set those headers could
bypass rate limiting and defeat the CSRF/method-override origin checks. 0.5.0
gives the whole framework one trust boundary and makes the safe default the
one you get when you say nothing.

**Before (`0.4`):** forwarded headers were honoured according to the rate
limiter's own settings, and other middleware made their own assumptions.

```toml
[security.rate_limit]
trusted_proxies = ["10.0.0.0/8"]
trust_forwarded_headers = true
```

**After (`0.5.0`):** one block, honoured by the rate limiter, the
method-override origin check, CSRF, HSTS detection and the tracing fields.

```toml
[security.trusted_proxies]
# Either name the proxies by CIDR ...
ranges = ["10.0.0.0/8"]
# ... or peel a fixed number of hops off the right of X-Forwarded-For.
# trusted_hops = 1
trust_forwarded_headers = true
```

Profile-aware defaults: `dev` trusts loopback only; `prod` trusts **no**
forwarding until this block is configured.

**If you are automating the upgrade:**

```bash
rg -n 'rate_limit' -A3 autumn.toml config/    # find the old keys
rg -n 'AUTUMN_SECURITY__RATE_LIMIT__TRUST' .  # and their env overrides
```

### Deprecated configuration keys

`security.rate_limit.trusted_proxies` and
`security.rate_limit.trust_forwarded_headers` keep working — they are
registered for removal in `1.0.0` — and log a deprecation warning at startup.
Move them to `[security.trusted_proxies]` now anyway: `autumn doctor --strict`
already **fails** when the old and new keys are set to conflicting values, and
the old keys take precedence over the new block where both are set, which is a
confusing place to leave a security boundary.

| Deprecated key (TOML / env var) | Replacement | Deprecated since | Removed in |
|---|---|---|---|
| `security.rate_limit.trusted_proxies` / `AUTUMN_SECURITY__RATE_LIMIT__TRUSTED_PROXIES` | `security.trusted_proxies.ranges` | `0.5.0` | `1.0.0` |
| `security.rate_limit.trust_forwarded_headers` / `AUTUMN_SECURITY__RATE_LIMIT__TRUST_FORWARDED_HEADERS` | `security.trusted_proxies.trust_forwarded_headers` | `0.5.0` | `1.0.0` |

### Reading client identity: `ClientAddr`, `ClientHost`, `ClientScheme`

**Why:** a handler that reads `X-Forwarded-For` itself re-opens the hole the
central policy just closed, because it applies no trust boundary at all.

**Before (`0.4`):**

```rust,ignore
let client_ip = headers
    .get("x-forwarded-for")
    .and_then(|value| value.to_str().ok())
    .unwrap_or("unknown");
```

**After (`0.5.0`):**

```rust,ignore
use autumn_web::extract::{ClientAddr, ClientHost, ClientScheme};

async fn handler(ClientAddr(addr): ClientAddr) -> impl IntoResponse {
    // `addr` is resolved through [security.trusted_proxies]; a spoofed header
    // from an untrusted peer never reaches you.
    format!("hello {addr}")
}
```

These extractors are the only supported way to read client identity — including
from plugins and custom middleware.

## Behavior changes

These compile fine and need no edit, but change what you observe at runtime:

- **Rate-limit and log identity.** With no `[security.trusted_proxies]` in
  `prod`, every request is attributed to the peer address — your proxy — so a
  per-IP rate limit becomes effectively global and access logs show one client.
  This is the visible symptom of skipping the step above.
- **Dev request inspector.** In the `dev` profile the framework mounts a request
  inspector at `/_autumn/inspect` (`[dev] inspector_path`). It does not exist in
  `prod` or `test`. If you already route `/_autumn/inspect`, rename one of them.
- **Generated `page` method.** `#[repository]` now emits `async fn page(&self,
  req: &PageRequest) -> AutumnResult<Page<Model>>` on the generated repository
  *trait*. If you hand-wrote an inherent `page` method on the same struct,
  nothing fails to compile — the inherent method silently wins at every call
  site, so `repo.page(..)` still runs your implementation, not the generated
  one. Rename one of them if you meant to use the generated pagination.

## About `with_pool` / `with_pool_untracked`

If you arrived here looking for the `with_pool` → `with_pool_untracked` rename
(#1273): **it is not part of 0.5.0.** The published 0.5.0 crates generate no
pool constructor at all — `with_pool` was both introduced and renamed inside the
0.6.0 development cycle. See
[`0.6.0.md`](0.6.0.md#repository-with_pool-is-renamed-to-with_pool_untracked).

## Compiler error cheat sheet

| Error message (truncated) | Where you see it | Fix |
|---|---|---|
| `error[E0034]: multiple applicable items in scope` — `page` | a call site, if you also have a *trait* with a `page` method in scope | disambiguate with `Trait::page(&repo, ..)` |
| `error[E0432]: unresolved import `autumn_web::extract::ClientAddr`` | you are still on 0.4 | the extractors landed in 0.5.0; check the dependency actually resolved |

Note there is no compile error for a hand-written *inherent* `page` — see
[Behavior changes](#behavior-changes).

## Troubleshooting

- **`WARN` at startup naming `security.rate_limit.trusted_proxies`** — the
  deprecation notice. Move the key to `[security.trusted_proxies]`.
- **`autumn doctor --strict` fails on trusted proxies** — the old and new keys
  disagree. Delete the old ones.
- **Rate limiting suddenly throttles everyone** — the proxy address is being
  used as the client identity. Configure `[security.trusted_proxies]`.
- **CSRF or method-override rejections behind a proxy** — the resolved host no
  longer matches `Origin` because the forwarded host is untrusted. Same fix.

## How to verify

1. `cargo check` and `cargo test` — green.
2. `autumn doctor --strict` — no findings, and no deprecation warning naming
   `security.rate_limit.*` in the startup log.
3. `grep -Rn 'x-forwarded\|X-Forwarded' src/` — no direct reads remain; client
   identity comes from `ClientAddr` / `ClientHost` / `ClientScheme`.
4. Send a request through your real proxy and confirm the access log records the
   **end-user** address, not the proxy's.
5. From an untrusted network, send `X-Forwarded-For: 1.2.3.4` directly to the
   app and confirm it is *ignored* — that header must not change the identity
   the app records.
6. Exercise a rate-limited endpoint from two different clients and confirm they
   are limited independently.

### Guide-only upgrade walkthrough

The release checklist requires upgrading an app scaffolded with `autumn new` on
the previous release using **only** this guide — no changelog, no source
reading. See [`docs/release-checklist.md`](../release-checklist.md), *Migration
Guide Gate*.

- **Status:** backfilled — this guide was written by #1588 after 0.5.0 shipped,
  so the guide-only upgrade was never performed for this release. It is a
  required, recorded step from the next release onward.

## Reporting problems

If you hit something this guide does not cover, that is a bug in the guide.
Open an issue at <https://github.com/autumn-foundation/autumn/issues> with the
error or unexpected behaviour, the version you upgraded from, and a minimal
reproduction if you have one.
