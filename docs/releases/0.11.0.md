# Autumn 0.11.0 — *Trust less, contract more*

A narrative tour of the release. The complete record is the
[`0.11.0` changelog entry](../../CHANGELOG.md#0110---2026-11-17); the upgrade
path from 0.10.x is the [migration guide](../migrations/0.11.0.md). This page
groups what shipped by what you are trying to do, and quotes the changelog's
own spellings rather than paraphrasing them.

0.10.0 gave one codebase several shapes of process. 0.11.0 is about what
crosses the line between them, and between an app and its clients: **less
implicit trust** (the tenant header, edge request headers, deploy values and
asset paths are all checked now), **wire contracts that reach past one
process** (events and outbox messages are contracts, nested types compare
field by field, and protobuf and Avro schemas export for consumers outside
the workspace), and **one database per boundary** (a Postgres role and schema
each, with grants the CLI writes and `autumn doctor` checks). Around those,
the fleet core stops depending on SQLite, background loops follow the
process role, and Kubernetes output gets one workload per role. Underneath
all of it, dates and times move from `chrono` to `jiff` 1.0, because
`chrono` and `chrono-tz` are now unmaintained.

## If you are upgrading

The release has 19 breaking changes, plus the move from `chrono` to `jiff`,
which reaches every date and time type an app names. Read
[*At a glance* in the migration guide](../migrations/0.11.0.md#at-a-glance)
first. The ones an application can meet:

- **`diesel-async` 0.10.** `autumn-web` moved to `diesel` 2.4 to close
  RUSTSEC-2026-0459. An app whose `Cargo.toml` names `diesel-async = "0.9"`
  (every app with a generated model does) moves it to `"0.10"`, and a SQLite
  app moves `libsqlite3-sys` to `"0.40"`. No code changes
  ([guide](../migrations/0.11.0.md#dependencies-diesel-async-010-and-libsqlite3-sys-040)).
- **Dates and times are `jiff`.** `chrono` (RUSTSEC-2026-0543) and
  `chrono-tz` (RUSTSEC-2026-0555) are unmaintained with no patched version,
  so the framework, plugins, CLI, generated code and examples dropped them.
  `DateTime<Utc>` becomes `autumn_web::time::Timestamp`, `NaiveDateTime`,
  `NaiveDate` and `NaiveTime` become `civil::DateTime`, `civil::Date` and
  `civil::Time`, and `chrono::Duration` becomes `SignedDuration`;
  `autumn_web::reexports::chrono` is gone. A `#[model]` field still typed
  with chrono fails to compile and the error names the jiff type. Remove
  `chrono` and diesel's `chrono` feature from your `Cargo.toml`, or chrono
  stays in your build. Printed values change shape (`2024-01-01T00:00:00Z`,
  not `2024-01-01 00:00:00 UTC`), and a model's JSON writes only the
  fraction digits it needs unless the field opts into
  `autumn_web::time::compat::serde_autosi`. Plugin authors with their own
  `BillingStore` or `RoomStore` update the signatures. An app generated by
  0.10.x moves by hand: `autumn upgrade` points at the section
  ([guide](../migrations/0.11.0.md#dates-and-times-chrono-is-replaced-by-jiff)).
- **The tenant header is not trusted by default.** `[tenancy] source` now
  defaults to `"session"`. `source = "header"` boots only with
  `header_trust = "trusted_proxy"` (the header counts from a peer in
  `security.trusted_proxies.ranges`, with
  `security.trusted_proxies.trust_forwarded_headers = true`) or
  `"any_client"` (the named unsafe opt-in). A session that holds the tenant binds the request to it: another
  tenant in a header, host name or token gets `403`
  ([guide](../migrations/0.11.0.md#tenancy-the-tenant-header-needs-header_trust)).
- **Edge handlers see only allowlisted headers.** `SENSITIVE_HEADERS` and
  `strip_sensitive_headers` are gone. Only `ALLOWED_REQUEST_HEADERS` —
  content negotiation, conditional requests, `cache-control` and
  `user-agent` — reach an `#[edge]` capsule, so an identity-aware proxy's
  `cf-access-jwt-assertion` cannot be echoed back
  ([guide](../migrations/0.11.0.md#edge-handlers-see-only-allowlisted-request-headers)).
- **A `default-features = false` build** names `cluster`, `reporting` (for
  failure capture), `plugin-conformance`, `runtime-config` or `axum-ws` if it
  uses them. A default build does not change.
- **`#[event]` is a wire contract.** It derives `WireShape`, so a generic,
  enum or `flatten` payload needs `#[event(opaque)]`, and an `#[event]` that
  derived `WireShape` drops the derive.
- **Struct literals** of `DatabaseConfig`, `DatabaseFleetConfig`,
  `TenancyConfig`, `OutboxConfig` and `DeployConfig` need the new fields;
  `MetricsSnapshot`, `CrateGraph` and `FleetStats` are `#[non_exhaustive]`.
- **A config section is a table.** `server = [8080, "0.0.0.0"]` loaded by
  field position before; now it fails boot with the key named.

Before you deploy: run `autumn migrate`. Two framework migrations add
indexes, each behind a short `SHARE` lock. A fleet of only `web` replicas
needs a `worker` for the media room reaper and recording sweep
([Behavior changes](../migrations/0.11.0.md#behavior-changes)).

Run `autumn upgrade` *before* bumping the dependency: it reads the version your
`Cargo.toml` still records and lists every break above with its guide section.

## Trust less by default

- **Tenancy** — a user of tenant A could send `x-tenant-id: B` and read or
  write tenant B's rows and shard. The header now needs
  `tenancy.header_trust`, and a session that holds `tenancy.session_key`
  binds every other source to it.
- **Edge capsules** — the Rust gateway, the JS host, the guest runtime and
  the native `#[edge]` mount keep only `ALLOWED_REQUEST_HEADERS`. The origin
  still gets every header.
- **Deploys** — `autumn deploy` and `autumn doctor` refuse a `[deploy]` host
  that `ssh` or `scp` can read as an option (`-oProxyCommand=…`), and a
  `service_name`, `app_name`, `profile`, `user` or `app_dir` that a remote
  shell or a unit file can read as code. Every `systemctl` operand is
  shell-quoted, and `scp` reaches an IPv6 host.
- **Assets** — `autumn assets` keeps every read and write in `static/`,
  refuses `..`, absolute and device paths in its manifest, and updates only
  from `https`.
- **Inbound mail** — the SES endpoint parses `SigningCertURL` and
  `SubscribeURL` and accepts only an SNS origin, so
  `https://sns.<region>.amazonaws.com@<other host>/…` no longer passes.
- **Dependencies** — `diesel` 2.4 / `libsqlite3-sys` 0.40 close
  RUSTSEC-2026-0459, and `ammonia` 4.2.5 closes RUSTSEC-2026-0533 for
  user-submitted rich text. `chrono` (RUSTSEC-2026-0543) and `chrono-tz`
  (RUSTSEC-2026-0555) are unmaintained, so Autumn moved to `jiff` 1.0, and
  the workspace `cargo deny` configs ban both crates so a feature cannot
  bring them back.

## Wire contracts across services

- **Events are contracts** — `#[event(name = "contact.updated", version =
  2)]` sends on `contact.updated.v2`, and a `#[listener]` that reads a field
  the event does not send fails the build, naming the event and the field.
  `#[event_consumer(E)]` gives an outbox topic handler the same check. See
  [Events](../guide/events.md).
- **Across releases** — `autumn contracts export` writes a byte-stable
  bundle of every wire descriptor, and `autumn contracts check --against
  <bundle|url|git-ref>` compares the build with a deployed release in both
  rolling-deploy windows. It fails on a removed response field a deployed
  caller reads or a new required request field it does not send, and exits
  `3` when a change is safe in one deploy order only.
- **Deeper comparisons** — nested `WireShape` types are compared field by
  field, `item.lines[0].price` reads as the path `lines.price` (through maud
  bindings, `@match`, loops and indexes), and each field records its JSON
  wire type, so a `DateTime<Utc>` that gets `#[serde(with = "ts_seconds")]`
  and `#[wire(type = "integer")]` is reported. `#[wire(type = "…", format =
  "…", nullable)]` names a type the macro cannot read (a `#[serde(with)]`
  field without it is `any`, which is not compared); `#[wire(opaque)]`
  compares by name only.
- **At the workspace edge** — `autumn contracts export --proto --out <dir>`
  writes protobuf schemas with a `proto.lock` that keeps field numbers, and
  `--avro` writes one `.avsc` per event topic for data pipelines. Neither
  needs `protoc` or an Avro dependency. ADR 0048 records why the Rust types
  stay the source and the IDL is an export. See
  [Wire contracts](../guide/wire-contracts.md).
- **Outbox delivery to another service** — `[outbox.destinations.<name>]`
  sends a topic to another service's `/_autumn/inbox`, signed with
  `Autumn-Signature`, with the outbox's at-least-once, per-aggregate order,
  jittered retry and dead-letter rules. `[outbox.inbox]` verifies the
  signature and records the message id with the listeners' work in one
  transaction, so a copy has no second effect. See
  [Outbox](../guide/outbox.md).

## One database, many boundaries

- **A role and a schema per boundary** (issue #3550) — `boundaries.toml`
  boundaries take `schema` and `role`, `[database.roles.<boundary>]` sets the
  connection, and `BoundaryDb<B>` / `AppState::pool_for::<B>()` hand out that
  role's pool. `#[repository(Model, boundary = Type)]` runs a repository as
  its boundary's role.
- **Grants you can read** — `autumn db grants` prints the `REVOKE` / `GRANT`
  statements of each role from `boundaries.toml` and the live catalog, and
  `--apply` runs them. `autumn doctor --strict` connects as each role and
  fails when one can reach a table outside its grant.
- **Schemas in the model** — `#[model(schema = "marketing")]`, with
  `schema diff --write-migration`, `schema pull --schema` and a qualified
  `table!` block. `autumn schema diff` matches foreign keys across schemas
  with one rule (ADR 0047).
- **Boundary checks that see more** — `autumn graph check-boundaries` puts a
  renamed `[[bin]]` target in its package's boundary, and a `*` pattern
  matches only tables in the graph.

## Fleets beyond SQLite

- **An engine seam** (issue #3642, ADR 0040) — the fleet core (keys, paths,
  single-flight opens, eviction, leases, ownership, fencing) no longer
  depends on SQLite, and compiles with `db` alone. An engine plugin
  implements `FleetEngine`, writes its own extractor over
  `fleet::resolve::<E>`, and runs `plugin_conformance::fleet` in its CI.
- **Shipping for every engine** — `ShipMode::Generations { every }` ships
  only the files whose SHA-256 changed since the last generation, core checks
  the fence before every replica write, and a close-time generation that did
  not ship is kept as unshipped work until it does.
  `replicated_through` / `wait_replicated` let a move delete its source row
  only once the new row is in the replica.
- **Limits that hold** — `max_resident_bytes` is a memory budget next to
  `max_open`, and `max_open_policy = "wait"` or `"refuse"` makes `max_open`
  hard, so a burst cannot fail with "too many open files".
- **Restores and lakes** — `autumn fleet restore <key> --from <file>` puts a
  local backup in place, checked and stamped. The fleet lake has a
  `LakeSink` seam that keeps its lake between loads.
- **SQLite tuning** — opt-in `mmap_size` and `cache_size_kib`, for the main
  database and for fleet databases separately. See
  [SQLite in production](../guide/sqlite-in-production.md#memory-mapped-reads-and-the-page-cache).

## Roles all the way down

- **Background tasks** (issue #3545) — `AppBuilder::background_task(name,
  capability, |state, shutdown| ..)` starts a loop only on the roles that run
  its capability, and the graceful drain waits for it. `/actuator/tasks` and
  `autumn graph` list each task with the roles that run it. The media room
  reaper, the recording sweep and the billing dunning re-arm moved onto it.
- **Plugin capabilities** — `PluginCapability::new("harvest.worker",
  Capability::JobWorkers)` follows its parent, and a named role turns it off
  with `[roles.<name>] capabilities = { "harvest.worker" = false }`. A new
  `maintenance` capability covers housekeeping loops.
- **One workload per role** (issue #3547) — `autumn release init --target
  kubernetes` writes a Deployment, PDB and optional HPA per role, and a
  Service, Ingress or rollout only for a role that serves HTTP. `--target
  fly` writes one `[processes]` entry per role.
- **Per-group deploy roles** — `[[deploy.groups]]` puts a role on a group of
  fleet hosts, and each release dir records its role, so a rollback keeps it.

## Reliability building blocks

- **`slo_meter::BurnMeter`** counts an SLO's good and bad events in process,
  and `firing(&BURN_WINDOWS[0])` asks the generated Prometheus alert's
  question, so an app can shed optional work while its budget burns.
- **`hedge::adaptive::AdaptiveHedge`** learns its hedge delay from a window
  of recent latencies (p95 by default), within `[floor, ceiling]`.
- **`RetrySchedule`** is a bounded full-jitter retry plan whose `run` loop
  stops when the next sleep would pass the request's `Deadline`.
- **Paged comment threads** (#3325) — `comment_thread_page` reads one page of
  top-level comments with all their replies, so the thread size no longer
  sets the cost.

## Faster requests and builds

- **The request path** does 10% to 14% fewer instructions and 11% to 14%
  fewer heap allocations on
  the `throttle_check`, `captcha_check` and `csrf_verify` workloads: a `GET`
  no longer parses `Accept`, the error page copies headers in dev only, and
  CSRF, bot protection and the rate limiter call the inner service in place.
  `AppState` is one `Arc`, so a clone is one reference count (issue #3168).
- **Queries that stop scanning** — a unique job with a TTL window, the
  commit-hook recovery tick and the concurrency-limited job claim each read a
  handful of buffers where they read the whole table (36,468 → 7.6, 23,794 →
  1 and 101,823 → 1,825 at the measured sizes).
- **Builds** — the config reader compiles one serde deserializer, the
  `cluster` module and three other subsystems are features, and new apps
  build dependencies without debug info. The no-DB daemon starter builds 12%
  faster from cold, and the gated cold-start budget dropped to p95 100 s.

## Toolchain and dependencies

Rust 1.97.0 stays the MSRV. `diesel` 2.4, `diesel-async` 0.10 and
`libsqlite3-sys` 0.40 are the carried dependency moves; see
[Upstream dependency updates](../migrations/0.11.0.md#upstream-dependency-updates).
`jiff` 1.0 replaces `chrono` and `chrono-tz`, with the IANA time zone
database bundled, so zone lookups do not depend on the host. The
framework's own JSON, SQLite text, ledger hash and HTTP date formats are
byte for byte what chrono wrote, so stored rows, ledger chains and
replayed capsules read as before
([Dates and times](../migrations/0.11.0.md#dates-and-times-chrono-is-replaced-by-jiff)).
